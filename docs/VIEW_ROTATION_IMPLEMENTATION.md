# 2.5D 시점 회전 구현 문서

> **상태: 보류.** 현재 우선순위는 [2D 포즈 키프레임 보간 계획](plans/POSE_INTERPOLATION_PLAN.md)이다. 이 문서는 기존 시점 회전 프로토타입의 동작 기록이며, 3D 시점 회전·카메라·원근 기능은 추가로 확장하지 않는다.

> **현재 구현 보충:** 관절 편집 좌표계는 이제 고정 정면 X/Y 평면이 아니라 현재 카메라 평면을 따른다. 화면 드래그는 월드 회전과 뷰 Y 회전을 역으로 적용한 카메라 `right/up` 벡터로 변환하고, 거리 유지 회전과 축·뼈대 핸들은 카메라 `forward` 벡터를 회전축으로 사용한다. 측면의 화면 가로 이동은 모델 깊이 Z 변경으로 변환된다.

## 1. 목적과 범위

이 기능은 3D 메시·카메라·물리 기반 렌더러를 구현하지 않는다. 관절 기반 2D 리그에서 정면과 좌·우 측면 사이의 **위치, 크기, 앞뒤 겹침 변화가 어떤 결과를 만드는지 확인하는 시뮬레이션**이다.

따라서 다음을 제공한다.

- 관절별 깊이와 전역 투영 강도
- 캔버스 세로축(Y축) 기준 시점 회전
- X/Z를 같은 규칙으로 회전하는 순수 시점 투영
- 정면 반지름과 측면 반지름의 보간
- 면·관절·가이드·히트 영역이 같은 파생 관절 크기를 사용하도록 하는 일관성

실제 타원 관절, 자유형 아트, 텍스처, 진짜 원근 카메라와 3D 법선은 이 단계의 범위 밖이다.

## 2. 핵심 원칙

### 면은 독립 도형이 아니라 관절 간 연결이다

면의 꼭짓점은 항상 `(jointId, axisId, side)` 참조에서 파생한다. 시점 회전 중에도 면을 별도로 이동·스케일하지 않는다.

```text
관절의 현재 시점 중심·반지름·축 방향
  → 관절별 화면 축 끝점
  → 면의 꼭짓점
  → 면 렌더링
```

따라서 관절의 화면상 크기가 바뀌면, 그 관절에 연결된 모든 면도 같은 반지름 기준으로 다시 생성된다.

### 화면상 직교는 정면 전용 규칙이다

정면에서는 관절 중심 연결선과 단면 축이 화면에서 직교한다. 그러나 3D 공간의 직교 관계는 일반 투영 뒤의 화면 2D 직교를 보장하지 않는다. 특히 완전 측면에서는 중심 연결선이 점 또는 짧은 선으로 수렴해 직교 방향을 안정적으로 정할 수 없다.

관절 중심과 조작축은 같은 X/Z 시점 변환을 적용한다. 연결 면은 변환된 관절 구의 카메라 방향 단면에서 직접 생성하므로 별도 면 경계축이 필요 없다. 완전 측면에서 폭이 0으로 수렴하는 것은 순수 회전의 결과로 유지한다.

## 3. 데이터 모델

```ts
interface Joint {
  radius: number;       // 정면(0°) 기준 반지름
  sideRadius?: number;  // ±90°에서 쓸 반지름. 없으면 radius 사용
  depth?: number;       // Z축 이동. 앞(+) / 뒤(-), 기본 0
}

interface Rig {
  perspectiveEnabled?: boolean; // false면 깊이 기반 크기 변화 없이 직교 투영
  projectionStrength: number; // 0..100
  viewYRotation: number;      // -90..90도
}

interface PeerGroup {
  jointIds: string[];            // 가상 캡슐은 정확히 두 관절일 때 사용
  centerJointId?: string;       // 선택적인 명시적 회전 중심
  virtualCapsule?: boolean;     // 두 구형 관절 사이에 파생 캡슐 표면 표시
}
```

`sideRadius`, `depth`, `viewYRotation`, `projectionStrength`는 JSON 프리셋에 선택적으로 저장한다. 이전 v1 프리셋에 이 값이 없으면 기본 리그 값과 정면 반지름을 유지한다.

## 4. 계산 순서

각 렌더 프레임의 순서는 아래와 같다.

1. 관절의 로컬 좌표와 계층으로 월드 중심을 계산한다.
2. `viewYRotation`과 `depth`를 적용해 화면 중심과 최종 깊이를 계산한다.
3. 정면 반지름과 측면 반지름을 보간한다.
4. 깊이 기반 투영 배율을 관절 반지름에 적용한다.
5. 관절 중심과 조작축에 같은 시점 변환을 적용한다.
6. 관절 구의 카메라 방향 단면을 이어 면을 생성하고, 깊이·그룹·레이어 순서로 렌더한다.

### 측면 반지름 보간

`t = abs(viewYRotation) / 90`으로 정규화한다.

```text
currentRadius = radius + (sideRadius - radius) × t
```

예를 들어 `radius = 48`, `sideRadius = 24`인 허리는 `0°`에서 48, `45°`에서 36, `±90°`에서 24가 된다.

### 순수 측면 투영

순수 Y축 투영은 `±90°`에서 같은 Z값의 X 좌표를 한 선으로 붕괴시킨다. 이 동작을 그대로 유지하며, 가로 실루엣을 인위적으로 남기는 보정은 적용하지 않는다.

## 5. 편집 방법

선택 패널에서 다음 순서로 조절한다.

1. `Y축 시점 회전`을 `±90°` 근처로 옮긴다.
2. 각 관절의 `Z축 이동`을 조절해 앞뒤 위치와 앞쪽 확대 정도를 맞춘다.
3. 허리·골반·어깨처럼 정면과 측면의 폭이 다른 관절은 `측면 반지름`을 설정한다.
4. `투영 강도`를 조절해 깊이에 따른 화면상 크기 변화를 정한다.
   `원근 적용`을 끄면 이 크기 변화만 제거하고 시점 회전과 깊이 순서는 유지한다.
5. 마지막으로 그룹/레이어 순서를 조절해 앞다리·뒷다리·몸통의 겹침을 확정한다.

두 관절 동등 그룹의 `가상 캡슐`을 켜면 관절 데이터와 부모·자식 관계는 합치지 않고 두 구형 관절 사이의 카메라 방향 원통 표면만 파생한다. 캡슐을 직접 선택하면 양 끝 관절이 한 쌍으로 선택되며, `캡슐 길이` 슬라이더·수치 입력·±1/±10 버튼으로 중심 간격을 조절한다. 변경 시 현재 중점과 연결 방향은 유지하고 양 끝 및 각 하위 트리를 대칭 이동한다. 명시적 가상 부모가 있으면 중심 오프셋과 그룹 회전 피벗은 기존 방식대로 독립 편집한다.

`±90°`는 기준 측면의 확인에 적합하며, 섬세한 직접 조작은 `±60°` 부근이 더 안정적이다. 깊이·시점 투영 때문에 역변환이 필요한 입력이 있기 때문이다.

## 6. 현재 한계와 후속 작업

- `sideRadius`는 원 반지름 하나를 보간하는 방식이다. 허리처럼 가로·세로가 다른 실제 타원 단면은 만들지 않는다.
- 하나의 면은 평균 깊이로 정렬되므로, 면 일부만 다른 면 앞에 와야 하는 깊이 교차는 해결하지 못한다.
- 숨김 관절 면 연장은 정면(`viewYRotation = 0`)에서만 사용한다. 시점 회전 중에는 새 화면 축 끝점과의 불일치를 피하기 위해 비활성화한다.
- 정면과 측면의 관절 위치·축 방향을 직접 저장하는 `ViewShapeKey`는 아직 없다. 현재 Y축 회전은 측면 배치를 위한 시뮬레이션·검증 단계다.

다음 단계에서는 `ViewShapeKey`에 정면·좌측·우측의 관절 위치, 반지름, 축 방향, 깊이 및 렌더 순서 보정을 저장하고, 두 키 사이를 보간한다. 실제 타원 또는 자유형 `ArtShape`는 그 이후에 추가한다.

## 7. 검증 기준

- `0°`에서 기존 정면 리그와 동일한 결과를 낸다.
- `±90°`에서 같은 Z값의 X 간격은 0으로 수렴하며, 인위적 실루엣 보정은 적용하지 않는다.
- 측면 반지름을 바꾸면 관절 표시, 축 끝점, 연결 면이 모두 같은 보간 반지름을 사용한다.
- 깊이와 시점 회전을 저장한 프리셋을 다시 열면 같은 결과가 복원된다.
- 포인터 입력은 투영된 화면 좌표를 원래 리그 좌표로 역변환해 관절 조작이 가능해야 한다.
