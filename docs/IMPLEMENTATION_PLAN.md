# Pose Mesh Editor 구현 계획

> 모델 변경 메모: 한 관절에서 생성되는 면마다 독립된 기울기를 가질 수 있도록 관절은 여러 축선을 가진다. 현재 인체 범위에서는 고관절의 골반 가로·세로 경계와 허벅지 연결을 위해 관절당 최대 3개를 허용한다. 축선을 배열로 저장하고 면이 `axisId`를 참조하므로 이후 제한도 늘릴 수 있다. 상세 규칙은 `GRAPHICS_GENERATION_SPEC.md`를 기준으로 한다.

## 1. 확인 결과

### 현재 구현된 부분

- Vite + TypeScript 앱과 실제 SVG 편집 화면이 준비되어 있다.
- 장면 루트와 머리·몸통·양팔·양다리 관절 계층, 어깨 띠·몸통·골반·사지 연결 면이 구현되어 있다.
- `Joint`, `JointAxis`, `JointPointRef`, `Face`, `Rig` 타입이 다중 축선 모델로 정의되어 있다.
- 관절 위치·반지름과 선택된 축선의 각도를 이용해 끝점 및 면 좌표를 구하는 `getAxisPoint()`, `getJointPoint()`, `getFacePoints()`가 구현되어 있다.
- 현재 최대 축선 수 3개와 면·그룹·팔레트·부모 관계의 참조 무결성을 검사하는 검증이 구현되어 있다.
- 관절 선택·이동, 반지름 조절, SVG 재렌더링이 동작한다. `Shift+클릭`과 사각 선택으로 여러 관절을 선택해 함께 이동·회전할 수 있다. `Shift+면 클릭`은 면을 구성하는 관절을 추가하고, 레이어 패널의 그룹 선택은 해당 그룹의 실제 관절을 한 번에 선택한다.
- 실행 취소/다시 실행, 휠 확대·축소, `Space+드래그` 화면 이동, 100% 초기화와 선택 맞춤을 지원한다. 연속 드래그와 슬라이더 변경은 실행 취소 한 단계로 묶는다.
- 직접 연결 면의 단면 축은 부모–자식 연결선과 직교한다. 축을 회전하면 해당 연결의 자식 관절, 연결 면과 전체 하위 관절이 함께 회전한다.
- 부모 변경 시 월드 포즈를 유지하며 순환 계층은 검증과 편집 API 양쪽에서 거부한다. 어깨와 고관절은 동등 관계 그룹 피벗 회전을 지원한다.
- 그룹과 항목별 레이어, 팔레트 연동 색상, 선택적 관절 표시, 외곽선과 관절 끝선 숨김을 지원한다.
- 포즈·비율·색상을 JSON v1 프리셋으로 저장하고 원하는 항목만 선택해 불러올 수 있다.
- PNG/SVG 저장 및 투명 배경 저장 미리보기가 구현되어 있다.
- Node 기본 테스트 실행기로 리그 검증, 계층 변환, 실행 취소/다시 실행, 프리셋 저장·복원을 자동 검증한다.
- 상대 경로 배포를 위한 Vite 설정(`base: "./"`)이 적용되어 있다.
- `main` 푸시 또는 수동 실행으로 GitHub Pages를 빌드·배포하는 워크플로가 있다.

### 현재 수정이 필요한 부분

- JSON 프리셋은 파일 저장·불러오기를 지원하지만 시스템 클립보드 복사·붙여넣기와 수동 텍스트 입력 대체 UI는 아직 없다.
- 자동 테스트는 데이터 계층을 다루지만 실제 브라우저 포인터 조작, 대화상자, PNG/SVG 다운로드의 종단 간 검증은 아직 없다.
- PWA 매니페스트·아이콘·서비스 워커가 없어 오프라인 설치형 앱으로 사용할 수 없다.
- 현재 레이어는 그룹 및 항목 단위다. `(jointId, faceId)`별 앞/뒤 관계와 깊이 충돌 분할은 구현되지 않았다.
- `canvas-renderer.ts`와 `pose-storage.ts`는 향후 확장을 위한 자리만 있으며 현재 기능에서는 사용하지 않는다.

### 현재 범위에서 제외할 부분

Canvas/WebGL 텍스처 변형, 애니메이션, 외부 이미지 가져오기, 손·발 그림 파츠와 유사 3D 시점 보간은 현재 범위에서 제외한다. 현재 면 색상과 팔레트는 단색 아트 및 연결 확인용이며 텍스처 재질을 의미하지 않는다.

## 2. MVP 완료 상태

기본 SVG 편집 MVP는 완료되었다. 5등신 기준선과 전체 기본 리그가 표시되며 관절 이동, 축선·연결 회전, 반지름·비율 편집, 다중 선택, 계층 변환, 색상·레이어 조절, 실행 취소/다시 실행이 동작한다. 결과는 JSON 프리셋과 PNG/SVG로 저장할 수 있다. 데이터 계층의 핵심 불변 조건은 `npm.cmd test`로 검증하고 프로덕션 결과는 `npm.cmd run build`로 확인한다.

## 3. 구현 원칙

1. 리그 데이터가 단일 진실 공급원이다. SVG 좌표를 직접 상태로 저장하지 않는다.
2. 축 끝점 좌표와 면의 점 목록은 렌더 시 계산한다.
3. 입력 계층은 상태만 변경하고, SVG를 직접 임의 수정하지 않는다.
4. 포인터 캡처를 사용해 SVG 밖으로 드래그해도 조작이 끊기지 않게 한다.
5. SVG의 `viewBox` 좌표로 포인터 위치를 변환해 창 크기와 무관하게 같은 리그 좌표를 사용한다.
6. 면과 출력용 관절 원은 계산된 렌더 순서로 정렬하고, 관절·축선 가이드는 그보다 나중에 렌더링한다.
7. `head`를 포함한 모든 실제 관절은 같은 부모–자식 변환 규칙을 사용한다. 현재 큰 머리 출력 원은 향후 관절 바인딩 `ArtShape`가 어떻게 움직일지를 보여 주는 임시 미리보기이며 관절 규칙의 예외로 취급하지 않는다. 모든 면은 ID를 해석하는 예외 코드 대신 `rotationTarget` 데이터로 자식 관절 또는 동등 그룹 회전 대상을 명시한다.
8. 부모와 자식 관절을 직접 참조하는 연결 면의 양 끝 축은 관절 연결선에 항상 직교한다. 관절 이동으로 연결 방향이 바뀌면 양 끝 축을 다시 정렬하고, 축 회전은 대응하는 자식 하위 트리의 회전으로 처리한다.
9. 다중 선택에 부모와 자식이 함께 들어 있으면 부모만 변환 루트로 사용해 하위 관절에 이동이나 회전이 중복 적용되지 않게 한다.

## 4. 권장 기본 규격

- SVG 논리 좌표: `600 × 800`
- 5등신 기준: 머리 단위 `120px`, 세로 기준선 5구간
- 기본 리그: 머리, 가슴 중심, 허리, 좌·우 어깨, 좌·우 팔꿈치, 좌·우 손목, 좌·우 고관절, 좌·우 무릎, 좌·우 발목. 가슴 중심은 기준 관절이며 반드시 면 꼭짓점일 필요는 없다.
- 관절당 축선: 현재 최대 3개. 고정 필드가 아니라 `axes[]`와 정책값으로 관리
- 연결 면: 어깨 띠 4점 면, 몸통 4점 면, 골반 중앙 4점 면과 좌우 3점 면, 양쪽 위팔·아래팔·허벅지·종아리의 4점 면
- 어깨 띠 순서: `왼쪽 어깨 위 → 오른쪽 어깨 위 → 오른쪽 어깨 아래 → 왼쪽 어깨 아래`
- 몸통 순서: `왼쪽 어깨 아래 → 오른쪽 어깨 아래 → 허리 오른쪽 → 허리 왼쪽`
- 골반 중앙 순서: `허리 왼쪽 → 허리 오른쪽 → 오른쪽 고관절 안쪽 → 왼쪽 고관절 안쪽`
- 골반 좌우 삼각형: 각 `허리 끝 → 고관절 바깥쪽 → 고관절 안쪽`
- 목 면: 하나의 `head` 관절과 가슴 중심 관절의 수평축을 연결한 4점 면. `head.radius`는 연결 폭으로 사용한다. 현재 `bodyRadius`로 그리는 큰 머리 원은 임시 `ArtShape` 미리보기이며, 아트 도형 단계에서 `head` 관절에 바인딩된 원 또는 자유 다각형으로 교체한다.
- 각도 단위: 데이터와 UI 모두 degree
- 최소 반지름: `8`, 최대 반지름: `80`

이 수치는 첫 화면의 일관된 구현을 위한 기본값이며, 코드에서는 상수로 분리해 이후 체형 변경에 대응한다.

## 5. 현재 작업 상태와 다음 작업

기존 작업 A~F의 기본 리그 연결 위상, 상체·골반·사지 면과 단색 아트 단계는 완료되었다. 아래 기록은 구현 근거로 유지한다. 다음 개발 우선순위는 다음과 같다.

1. 포즈·비율 JSON을 시스템 클립보드로 복사·붙여넣고, 권한이 막힌 환경을 위한 텍스트 입력 대체 UI를 제공한다.
2. 브라우저 종단 간 테스트를 추가해 포인터 조작, 저장 대화상자와 PNG/SVG 출력을 검증한다.
3. 웹 앱 매니페스트와 서비스 워커를 추가해 오프라인 설치와 업데이트 알림을 지원한다.
4. `(jointId, faceId)`별 앞/뒤 관계와 깊이 충돌 정책을 확정한다.

### 완료 기록 — 기본 리그 연결 위상

### 작업 A — 현재 데이터 흐름 읽기

1. `src/rig/types.ts`에서 `Joint.axes`와 `Face.vertices`의 참조 구조를 확인한다.
2. `src/rig/geometry.ts`에서 `(jointId, axisId, side)`가 화면 좌표로 변환되는 과정을 확인한다.
3. `src/rig/default-rig.ts`에서 현재 상체와 팔 면의 꼭짓점 순서를 종이에 그려 본다.

완료 기준: 코드를 수정하지 않고도 특정 `Face.vertices` 항목이 화면의 어느 점인지 설명할 수 있다.

### 작업 B — 관절 목록과 축선 역할 수정

1. `default-rig.ts`의 `pelvis`를 역할이 분명한 `waist`로 정리한다.
2. 좌우 무릎과 발목 관절을 추가한다.
3. 어깨에는 `torso`/`upper-arm`, 허리에는 `upper-torso`/`pelvis`, 고관절에는 `pelvis`/`upper-leg` 축을 둔다.
4. 팔꿈치에는 `upper-arm`/`lower-arm`, 무릎에는 `upper-leg`/`lower-leg`, 손목·발목에는 끝 사지용 축을 둔다.

완료 기준: 모든 관절이 현재 최대 3개 축선 규칙을 지키고, 축선 ID만 보아도 어느 면이 사용하는지 알 수 있다.

### 작업 C — 어깨 띠와 몸통 면으로 교체

기존 `chest ↔ pelvis` 상체 면을 다음 두 개의 4점 면으로 교체한다.

```text
어깨 띠:
왼쪽 어깨 torso축 위쪽
→ 오른쪽 어깨 torso축 위쪽
→ 오른쪽 어깨 torso축 아래쪽
→ 왼쪽 어깨 torso축 아래쪽

몸통:
왼쪽 어깨 torso축 아래쪽
→ 오른쪽 어깨 torso축 아래쪽
→ 허리 upper-torso축 오른쪽
→ 허리 upper-torso축 왼쪽
```

완료 기준: 두 면이 같은 어깨 아래쪽 참조를 공유해 틈이 없고, 어깨의 `torso` 축을 회전하면 어깨 띠와 몸통만 변하며 팔은 변하지 않는다.

### 작업 D — 골반 사각형과 좌우 삼각형 추가

중앙 사각형과 좌우 삼각형을 별도 `Face`로 기록한다.

```text
중앙: 허리 왼쪽 → 허리 오른쪽 → 오른쪽 고관절 안쪽 → 왼쪽 고관절 안쪽
왼쪽: 허리 왼쪽 → 왼쪽 고관절 안쪽 → 왼쪽 고관절 바깥쪽
오른쪽: 허리 오른쪽 → 오른쪽 고관절 바깥쪽 → 오른쪽 고관절 안쪽
```

완료 기준: 세 면이 경계를 공유해 틈이 없고, 골반 회전 중에도 사각형과 삼각형이 같은 회전량을 유지한다.

### 작업 E — 다리와 끝 관절 연결

1. 고관절 `upper-leg` 축과 무릎 `upper-leg` 축으로 허벅지 면을 만든다.
2. 무릎 `lower-leg` 축과 발목 `lower-leg` 축으로 종아리 면을 만든다.
3. 손목·발목 관절은 리그와 축선을 항상 유지한다.
4. `bodyVisible`로 손목·발목 관절부를 덮을지 선택한다.

완료 기준: 관절부 출력을 숨겨도 면 계산은 유지되고, 표시하면 관절 원이 면 끝을 덮는다.

### 작업 F — 연결 확인 후 아트 단계 보류

현재는 `Rig.defaultColor` 하나로 전체 기본색을 정하고, 사용자가 명시한 면에만 선택적인 `Face.color`를 저장한다. 기본 리그에는 면별 색상을 지정하지 않는다. 이후 `materialId`, 외부 `TextureAsset`, 삼각형/UV 매핑을 별도 단계로 설계한다.

## 6. 기존 단계별 구현 기록

### 단계 1 — 리그 상태 기반 마련

대상 파일:

- `src/rig/types.ts`
- `src/rig/rig-state.ts`
- `src/rig/geometry.ts`

작업:

- 선택된 관절 ID와 축선 ID를 편집기 상태로 관리한다.
- 관절 조회·선택·위치 이동·반지름 변경과 축선 조회·선택·각도 변경 API를 `RigState`에 추가한다.
- 현재 축선 수 제한과 잘못된 관절/축선/끝점 참조를 조기에 찾는 검증을 유지·확장한다.
- 각도 정규화와 반지름 범위 제한을 한곳에서 처리한다.
- 상태 변경 시 렌더 갱신을 요청할 수 있도록 간단한 구독 함수를 제공한다.

완료 조건:

- 존재하지 않는 ID로 상태를 변경해도 앱 전체가 불명확하게 실패하지 않고 원인을 알 수 있다.
- 모든 편집 동작이 `RigState` API를 통해서만 이루어진다.

### 단계 2 — 기본 5등신 리그 데이터 작성

대상 파일:

- `src/rig/default-rig.ts`

작업:

- 기본 관절과 가상 장면 루트의 ID, 위치, 반지름, 축선 배열, 렌더 순서, 표시 여부를 정의한다.

## 8. 주요 위험과 대응

### SVG 좌표 오차

CSS 크기와 `viewBox` 크기를 혼용하면 드래그 위치가 어긋난다. 모든 입력을 역변환 행렬로 SVG 좌표에 맞춘다.

### 회전 시 면 뒤집힘

렌더 중 최근접점이나 교차점을 다시 찾지 않는다. 면의 `(jointId, axisId, side)` 배열 순서를 위상으로 고정하고 해당 축 끝점 좌표만 갱신한다.

### 상태와 DOM 불일치

포인터 이벤트에서 원의 `cx`, `cy`를 직접 바꾸지 않는다. 상태 변경 후 한 렌더 경로를 통해 화면을 갱신한다.

### 이후 기능과의 결합

포즈 저장과 Canvas 렌더러는 MVP 상태 모델을 소비하도록 만들 예정이므로, 편집기 전용 속성을 `Joint`에 계속 추가하지 않고 별도 `EditorState`로 분리한다.

1. **완료 — 저장 스키마 버전 도입**: 포즈·비율·색상을 담는 `pose-mesh-editor` JSON v1 형식과 구형 골반 피벗 데이터 마이그레이션 경계를 구현했다.
2. **부분 완료 — 포즈·비율 복사/붙여넣기**: 파일 기반 JSON 저장·선택 불러오기와 유효성 검사는 구현했다. 시스템 클립보드와 텍스트 영역 기반 수동 복사·붙여넣기는 다음 작업이다.
3. **다음 작업 — 오프라인 설치형 앱(PWA)**: 웹 앱 매니페스트, 아이콘, 서비스 워커를 추가해 브라우저의 설치 기능으로 프로그램을 내려받을 수 있게 한다. 앱 셸과 정적 에셋은 캐시 우선으로 제공하고, 새 배포본은 사용자에게 업데이트 가능 상태를 알린다. 오프라인에서는 네트워크가 필요한 외부 이미지 가져오기만 비활성화하며, 편집·포즈/비율 복사·PNG/SVG 출력은 계속 동작해야 한다.
4. **완료 — 관절 로컬/월드 계층**: `parentJointId`와 로컬 위치·회전, 월드 변환 파생, 하위 트리 전파, 부모 변경 시 월드 포즈 유지와 순환 방지를 구현했다. 어깨·고관절 동등 관계 그룹 회전도 지원한다.
5. **관절별 면 앞뒤 관계**: `(jointId, faceId)`마다 `-1`/`+1`과 같은 부호 내 보조 순서를 저장한다. 한 부호에 여러 면을 허용한다.
6. **깊이 충돌 처리**: 한 면이 관절마다 상반된 깊이를 가질 때 단일 SVG 다각형으로 해결할지, 삼각형/렌더 조각으로 분할할지 구현 범위를 확정한다.
7. **자유 다각형 `ArtShape`**: 얼굴형, 머리카락, 옷, 장식을 리그 연결 면과 분리된 도형으로 추가·편집·삭제한다.
8. **관절/면 가중치 바인딩**: 도형과 정점이 상위 관절 또는 면을 따라가는 정도를 이동·회전·변형 파라미터로 조절한다.
9. **면 삼각형과 barycentric 좌표**: 면에 붙는 옷과 얼굴 요소가 면의 변형과 이동을 안정적으로 따라가게 한다.
10. **유사 3D 시점 변형 — 보류**: 정면과 좌·우 측면의 기준 형상을 같은 위상으로 저장하고, 시점 각도에 따라 관절·면·`ArtShape`를 보간해 중간 방향 이미지를 만든다. 단순 가로 축소가 아니라 실루엣, 중심 이동, 겹침 순서와 파츠 표시 여부를 함께 변형한다. 현재 단계에서는 구현하지 않고, 2D 그룹 렌더 순서와 겹침 경계가 안정된 뒤 재개한다.
11. **저장·출력 통합**: 프로젝트 JSON에는 편집 가능한 로컬 좌표와 바인딩, 시점 기준 형상을 저장하고, PNG/SVG에는 계산된 최종 도형을 출력한다.
12. **부분 완료 — 자동 검증**: 현재 테스트는 기본 리그 무결성, 잘못된 참조와 부모 순환, 하위 트리 회전, 부모 변경, 실행 취소/다시 실행, JSON 프리셋 복원을 검사한다. 가중치·깊이 충돌·자기 교차·삼각형 뒤집힘·시점 보간 검사는 해당 기능 구현 시 추가한다.

완료 기준:

- 어깨를 회전하면 팔꿈치와 손목이 계층을 따라 이동하고 각 하위 관절의 로컬 포즈는 유지된다.
- 같은 관절 앞이나 뒤에 여러 면을 배치할 수 있으며 결과 순서가 저장 후에도 동일하다.
- 얼굴형 도형은 머리를 이동하면 함께 움직이고, 회전 영향값에 따라 자연스럽게 회전한다.
- 옷 도형은 연결된 관절과 면을 따라가며 가중치를 바꿀 때 변형 강도가 연속적으로 변한다.
- 정면과 측면 사이의 시점 슬라이더를 움직이면 관절·외곽선·얼굴 요소와 가림 순서가 끊기지 않고 연속적으로 변한다.
- 프로젝트를 다시 열었을 때 계층, 깊이, 다각형과 모든 영향값이 복원된다.
- 포즈 또는 비율 데이터를 복사해 다른 브라우저·오프라인 설치 앱에 붙여 넣어도, 호환되는 리그에서는 같은 결과가 복원된다.
- 네트워크를 끈 뒤 설치된 앱을 다시 열어도 기본 리그 편집과 PNG/SVG 출력이 가능하다.

### 계층 조작 UI와 회전 보조선

계층화 구현에서는 데이터 구조만 바꾸지 않고, 편집자가 부모 관계와 회전을 직관적으로 조작할 수 있는 UI를 함께 제공한다.

1. **관계 종류와 회전 중심**: 관절 관계는 `parent-child`와 `peer`로 구분한다. `parent-child`는 실제 변환 계층이며, 자식 및 그 하위 트리는 부모 관절 중심을 회전 중심으로 사용한다. 팔은 `shoulder → elbow → wrist`의 부모–자식 관계로 구성한다. `peer`는 변환 부모를 만들지 않는 동등 관계이며, 구성원의 현재 월드 좌표에서 계산한 가상 중심점을 회전 중심으로 사용한다. 기본 어깨 띠는 `left-shoulder`와 `right-shoulder`의 동등 관계이며, 가상 중심은 두 관절 중심의 중점이다.
2. **부모 선택 UI**: 선택한 관절의 속성 패널에 `부모 관절` 드롭다운을 표시한다. 최상위 관절은 `없음`을 선택할 수 있다. 현재 관절 자신, 해당 관절의 모든 하위 관절, 존재하지 않는 ID는 선택지에서 제외한다. 동등 관계는 별도 `동등 관절 그룹` UI로 관리하며, 같은 그룹의 구성원은 부모–자식으로 자동 변환하지 않는다.
3. **계층·동등 관계선 표시**: 편집 가이드가 보일 때 부모–자식 관절 중심을 잇는 선을 렌더링한다. 동등 관계는 구성원과 가상 중심점을 잇는 별도 가이드로 표시하며, 가상 중심점에는 작은 다이아몬드 핸들을 둔다. 두 선 유형은 면 윤곽과 서로 구별되는 스타일을 사용한다.
4. **연결선 기반 회전**: 부모 관절을 선택했을 때 각 직접 자식으로 향하는 연결선을 회전 조작 영역으로 제공한다. 선 또는 끝 핸들을 드래그하면 부모–자식 사이의 로컬 방향을 바꾸고, 그 자식과 모든 하위 관절은 부모 관절 중심을 기준으로 함께 회전한다. 거리는 유지한다. 연결선 양 끝 관절의 해당 축은 같은 회전량을 유지하며, 두 관절이 공유하는 면의 부모 쪽 축도 함께 회전시켜 면이 늘어나거나 찌그러지지 않게 한다. 동등 관계 그룹의 가상 중심 핸들을 드래그하면 그룹 구성원이 해당 가상 중심을 기준으로 함께 회전하며, 구성원 간 거리와 각도는 유지한다.
5. **드래그 역할 구분**: 관절 중심 드래그는 선택한 관절의 위치를 조정한다. 부모–자식 연결선/끝 핸들 드래그는 해당 하위 트리의 회전만 조정하고, 동등 관계의 가상 중심 핸들 드래그는 그룹 회전만 조정한다. 세 조작의 커서·강조 상태를 다르게 표시해 의도를 명확히 한다.
6. **변환 기준**: 부모 관절을 이동하면 하위 관절은 같은 변환을 받는다. 자식 연결선을 회전하면 그 자식 하위 트리만 회전하며, 형제 관절과 부모의 다른 자식은 움직이지 않는다. 동등 관계 그룹을 회전하면 그룹 구성원만 가상 중심을 기준으로 움직이며, 각 구성원의 자식 트리도 함께 움직인다. 월드 좌표 직접 입력 또는 드래그는 내부적으로 새 부모 기준의 로컬 값으로 역변환한다.

완료 기준:

- 속성 패널에서 부모를 바꿔도 관절의 현재 화면 위치와 하위 관절의 월드 포즈가 갑자기 바뀌지 않는다.
- 어깨–팔꿈치 연결선을 회전하면 해당 팔꿈치·손목만 호를 그리며 회전하고, 반대쪽 팔과 몸통은 유지된다.
- 어깨–팔꿈치 연결선을 회전하는 동안 위팔 면의 네 꼭짓점은 같은 회전량을 받아 면의 폭·각도·사다리꼴 형태를 유지한다.
- 왼쪽·오른쪽 어깨의 가상 중심 핸들을 회전하면 두 어깨와 각 팔 전체가 중점을 기준으로 함께 회전하며, 어깨 사이 간격은 유지된다.
- 순환 부모 관계는 UI와 데이터 검증 양쪽에서 만들 수 없다.

### 골반 가상 피벗 규칙

골반은 양 고관절만 중점을 중심으로 돌리면 `pelvis` 면의 허리 쪽 꼭짓점이 남아 면이 찌그러진다. 따라서 골반 회전은 별도 가상 피벗과 연결 면 단위의 변환으로 처리한다.

1. 가상 피벗은 두 고관절 중심의 중점에 두며, `waist`의 자식 변환 노드로 저장한다. 양 고관절과 하위 다리는 이 가상 피벗의 자식으로 둔다. 편집 가이드에는 보라색 다이아몬드 핸들로 표시한다.
2. 하체 회전 조작은 골반 중앙 사각형과 좌우 삼각형에 참여하는 두 고관절 및 각 하위 트리에 같은 회전 행렬을 적용한다. 회전 후에도 허리–고관절 간 거리와 세 면의 형태를 유지한다.
3. `pelvis` 면에 쓰이는 허리·양 고관절 축은 피벗 회전량을 함께 적용한다. 이 축을 다른 면과 공유할 경우에는 독립 축을 추가하거나 면을 분할해, 다른 면이 의도치 않게 변형되지 않도록 한다.
4. 골반 피벗 회전은 허리 굽힘(`waist → chest` 연결선 회전)과 별도 조작이다. 전자는 상체만, 후자는 골반과 양 다리 및 연결된 하위 요소를 움직인다.
5. 좁은 가상 연결선에 의존하지 않고 중앙 사각형 내부의 가상 피벗에서 골반 오른쪽 바깥으로 뻗는 전용 `하체 회전` 핸들을 제공한다. 핸들은 실제 골반 방향과의 각도 오프셋을 보존해 드래그 시작 시 도형이 튀지 않게 한다. 속성 패널에는 상체 기준 `-180°..180°` 슬라이더와 숫자 입력을 함께 둔다.

### 유사 3D 시점 회전 변형

> **현재 상태: 구현 보류.** 아래 내용은 후속 구현을 위한 설계 기록이며, 현재 편집기에는 `viewAngle`이나 기준 형상 보간을 추가하지 않는다. 우선 2D 포즈에서 그룹 렌더 순서와 겹침 경계를 안정화한다.

이 기능의 목적은 실제 3D 메시를 회전시키는 것이 아니라, 동일 캐릭터의 **정면과 측면 기준 형상 사이를 2D 변형으로 연결해 중간 시점 이미지를 만드는 것**이다. 캐릭터 포즈와 카메라 방향을 분리하기 위해 시점 회전은 관절의 자세 회전과 다른 `viewAngle` 상태로 관리한다.

#### 데이터와 기준 형상

1. 시점 각도는 정면 `0°`, 오른쪽 측면 `+90°`, 왼쪽 측면 `-90°`로 정의하고 `-90..90` 범위에서 편집한다. 첫 구현은 정면↔오른쪽 측면 한 구간으로 검증한 뒤 왼쪽을 추가한다.
2. `ViewShapeKey`는 각 기준 각도에서 관절의 2D 위치·반지름·축 각도 보정값, 리그 면과 `ArtShape` 정점 보정값, 깊이 순서와 파츠 표시 상태를 저장한다. 포즈 원본을 복제하지 않고 기본 포즈에 적용되는 시점별 보정값으로 분리한다.
3. 정면과 측면 기준 형상은 같은 관절 ID, 면 ID, 정점 ID와 삼각형 위상을 사용해야 한다. 시점마다 정점 수나 순서가 달라지는 도형은 직접 보간하지 않고 대체 파츠 또는 단계적 표시 규칙을 사용한다.
4. 좌우가 완전히 대칭인 캐릭터는 오른쪽 측면 키를 반전해 왼쪽 초안을 만들 수 있다. 머리카락, 의상, 흉터처럼 비대칭인 요소는 좌·우 키를 각각 저장한다.

개념 데이터는 다음 구조를 기준으로 구체화한다.

```ts
interface ViewShapeKey {
  angle: number; // -90..90, 0과 ±90은 필수이고 ±45 등 보정 키를 추가할 수 있음
  jointOffsets: Record<string, { x: number; y: number; radiusScale?: number; angleOffset?: number }>;
  vertexOffsets: Record<string, { x: number; y: number }>;
  depthOverrides?: Record<string, number>;
  visibility?: Record<string, number>; // 0..1, 교체 파츠의 페이드에도 사용
}

interface ViewState {
  viewAngle: number; // -90..90
  keys: ViewShapeKey[];
}
```

#### 변형과 렌더 규칙

1. 현재 `viewAngle`을 감싸는 두 기준 키를 찾고 정규화된 `t`로 보간한다. 위치·반지름·자유 정점은 선형 보간으로 시작하되, 얼굴 윤곽과 코처럼 곡률이 중요한 요소는 이후 보정 키(`±45°`) 또는 곡선 보간을 추가할 수 있게 한다.
2. 각도는 수치 자체를 단순 보간하지 않고 최단 회전 경로로 보간한다. 정면에서 측면으로 갈 때 좌우 폭만 줄이는 방식은 사용하지 않으며, 코·턱·후두부·어깨·골반처럼 실루엣을 만드는 정점은 기준 키의 실제 위치 보정을 따른다.
3. 계산 순서는 `포즈 로컬값 → 관절 월드 변환 → 시점별 관절 보정 → 리그 면 → 시점별 정점 보정/면 바인딩 → 깊이·표시 보간 → 렌더`로 고정한다. 같은 포즈에서 시점만 바꾸어도 관절 계층 자체와 포즈 데이터는 변하지 않아야 한다.
4. 깊이는 실수값으로 보간하되 실제 그리기 직전에 안정적으로 정렬한다. 눈·귀·팔처럼 앞뒤가 바뀌는 요소는 교차 각도와 동률 정렬 규칙을 명시해 프레임마다 순서가 떨리지 않게 한다.
5. 측면에서 사라지거나 반대편 파츠로 교체되는 요소는 임계값에서 갑자기 삭제하지 않는다. 가능한 경우 `visibility`를 보간하고, 위상이 다른 파츠는 짧은 교차 페이드와 명시적 전환 각도를 사용한다.
6. 편집용 SVG 미리보기, Canvas/WebGL 아트 렌더러, PNG/SVG 출력은 모두 동일한 최종 변형 좌표와 깊이 결과를 사용한다.

#### 편집 UI와 구현 순서

1. 속성 패널에 `시점 각도` 슬라이더와 숫자 입력을 추가하고 `정면`, `왼쪽 측면`, `오른쪽 측면` 기준 키로 바로 이동하는 버튼을 제공한다.
2. 기준 키 편집 모드에서는 현재 각도의 관절·면·`ArtShape` 보정값만 수정한다. 중간 각도에서는 결과를 미리 보되, 사용자가 수정하려 하면 새 보정 키를 만들지 기존 양끝 키를 수정할지 명확히 선택하게 한다.
3. 1차 검증은 머리·얼굴 윤곽·눈·코처럼 시점 변화가 분명한 작은 샘플로 진행한다. 이후 몸통과 골반, 팔다리, 머리카락과 의상 순서로 범위를 넓힌다.
4. 중간 시점에서 자기 교차, 삼각형 뒤집힘, 폭이 0에 가까워지는 면, 깊이 순서 동률을 검사하고 편집 화면에 경고한다.
5. 기준 키와 `viewAngle`은 프로젝트 저장 대상에 포함한다. 포즈 프리셋은 기본적으로 시점과 분리하되, 스토리 컷 프리셋에서는 포즈와 시점을 함께 참조할 수 있게 한다.

완료 기준:

- 정면 `0°`와 측면 `±90°`에서는 사용자가 작성한 기준 형상이 오차 없이 재현된다.
- `0° → 90°` 및 `0° → -90°` 전 구간에서 관절, 실루엣과 얼굴 요소가 연속적으로 이동하며 면의 정점 순서가 바뀌지 않는다.
- 눈·귀·팔 등 겹침 관계가 바뀌는 요소는 지정된 각도에서 안정적으로 앞뒤가 전환되고 깜빡임이 없다.
- 같은 포즈에서 시점 각도를 왕복해도 원래 포즈 데이터와 기준 형상 데이터가 누적 변형되지 않는다.
- 중간 시점 그대로 PNG/SVG로 저장했을 때 편집 미리보기와 동일한 결과가 나온다.

## 11. 최종 MVP 인수 기준

- 기본 5등신 가이드와 15개 편집 관절이 보인다.
- 관절을 선택하고 중심을 드래그할 수 있다.
- 선택 관절의 반지름을 조절할 수 있다.
- 한 관절에서 축선을 선택하고 각 축선의 각도를 독립적으로 바꿀 수 있다.
- 오른팔 면이 네 축 끝점으로 생성되며 해당 축선 편집에 즉시 반응한다.
- 면의 꼭짓점 순서와 계산된 렌더 순서가 안정적으로 유지된다.
- 기본 검증은 관절당 축선을 최대 3개로 제한하지만 데이터 모델은 추가 축선을 수용할 수 있다.
- 관절 가이드를 숨길 수 있는 데이터 구조가 유지된다.
- TypeScript 프로덕션 빌드가 성공하고 브라우저 콘솔 오류가 없다.
- `npm.cmd test`의 데이터 계층 회귀 테스트가 모두 통과한다.
