# 다음 작업 일정 — 게임 리소스 출력과 편집 확장

이 문서는 체형·포즈 분리와 v3 프로젝트 파일 검증을 완료한 뒤 진행할 작업을 실행 순서대로 정리한다. 정확한 날짜나 소요 시간은 정하지 않고, 각 단계의 선행 조건과 검증 결과로 다음 단계 진입 여부를 판단한다. 현재 상태의 요약은 [현재 작업 진행 순서와 완료도](CURRENT_WORK_PLAN.md)를 기준으로 한다.

## 전체 일정

| 작업 단위 | 내용 | 상태 | 진입 조건 | 완료 결과 |
| ---: | --- | --- | --- | --- |
| A | 게임용 애니메이션 패키지 출력 | 다음 작업 | 기존 PNG/SVG 프레임 ZIP과 v3 왕복 검증 완료 | 스프라이트 시트 PNG와 메타데이터 JSON 실제 파일 검증 |
| B | 출력 표현력 확장 | 대기 | A 완료 | 의상 튜브 셸과 출력 그룹별 병합 SVG |
| C | 저장·애니메이션 편집 후속 이전 | 대기 | A의 출력 계약 안정화 | v3 자동 저장, 여러 클립 선택과 복원 |
| D | 범용 관절·도형 구조 편집 | 대기 | 저장 형식과 실행 취소 경계 확정 | 관절·축·면 생성/삭제와 캡슐·사각형 확장 기준 선택 |

각 작업 단위는 자동 테스트와 프로덕션 빌드에 더해 실제 파일 또는 실제 편집 조작 검증을 통과해야 완료로 처리한다.

## 최소 기준까지 남은 필수 작업

현재 정의한 게임 리소스 출력 최소 기준은 **작업 단위 A와 B를 끝내고, 실제 에셋 통합 검증을 통과하는 것**이다.

1. 고정 피벗·공통 경계·루트 이동 분리 규칙 확정
2. 균일 그리드 PNG 스프라이트 시트 출력
3. FPS·재생 방식·프레임 좌표·피벗·루트 이동을 담은 JSON 메타데이터
4. 시트 프레임과 기존 PNG ZIP 프레임의 일치 검증
5. 재사용 가능한 튜브 단면과 의상용 튜브 셸
6. 출력 그룹별 SVG 병합과 내부선 제거
7. 부분 교차 경고와 비교차 포즈 안정성 검증
8. 실제 게임 에셋 하나로 PNG·JSON·SVG·재불러오기 통합 검증

작업 단위 C–E인 v3 자동 저장, 범용 관절 편집과 고급 카메라는 최소 기준 달성 후의 확장 작업으로 구분한다.

## A. 게임용 애니메이션 패키지 출력

### 목표

이미 검증된 애니메이션 프레임을 다시 설계하지 않고, 게임에서 바로 사용할 수 있는 투명 PNG 스프라이트 시트와 JSON 메타데이터로 포장한다. 기존 개별 PNG/SVG 프레임 ZIP 출력은 유지한다.

### A1. 출력 좌표와 루트 이동 계약

| 항목 | 결정 또는 구현 내용 | 완료 기준 |
| --- | --- | --- |
| 공통 경계 | 모든 baked 프레임의 투영 결과를 같은 출력 좌표계에서 합친 경계를 셀 크기로 사용 | 팔·다리·월드 회전의 최대 범위가 어떤 프레임에서도 잘리지 않음 |
| 안전 여백 | 공통 경계 바깥에 명시적인 픽셀 여백을 선택적으로 추가 | 여백이 셀마다 달라지지 않고 메타데이터에 반영됨 |
| 고정 피벗 | 렌더 경계와 별도로 캐릭터 배치 기준을 정의 | 모든 프레임이 같은 피벗 좌표를 사용해 재생 중 화면 기준이 흔들리지 않음 |
| 루트 이동 | 기본 출력은 루트 이동을 이미지 위치에 누적하지 않고 프레임별 이동값으로 분리 | 제자리 재생과 게임 오브젝트 이동을 독립적으로 재현할 수 있음 |
| 포함 모드 | 필요한 경우 루트 이동을 이미지 안에 굽는 선택지를 후속 제공 | 첫 구현의 필수 범위가 아니며 기본 모드와 혼동되지 않음 |

권장 기본값은 **고정 피벗 + 전체 동작의 공통 경계 + 루트 이동 메타데이터 분리**다. 투명 여백은 캐릭터를 임의로 축소하기 위한 공간이 아니라, 고정된 기준점에서 모든 동작을 잘리지 않게 담는 공간이다.

### A2. 메타데이터 스키마

다음 정보를 저장하는 버전 명시 JSON 형식을 확정한다.

- 연결된 PNG 파일명과 전체 이미지 크기
- 셀 너비·높이, 열·행 개수와 안전 여백
- FPS와 `loop`/`ping-pong` 재생 방식
- baked 프레임 순서와 원래 애니메이션 프레임 번호
- 각 프레임의 시트 `x/y/width/height`와 지속 시간
- 공통 피벗 좌표
- 루트 이동을 분리할 경우 프레임별 X/Y/Z 이동량
- 고정 `outputView`와 `worldRotationTrack` 적용 여부를 판별할 형식 버전

완료 조건은 JSON만 읽어도 시트 자르기, 재생 순서, 피벗 배치와 루트 이동을 재현할 수 있는 것이다.

### A3. 균일 그리드 배치 계산

1. 기존 `bakePoseClipFrames()` 결과를 입력으로 사용한다.
2. 프레임 개수와 설정한 열 개수로 행 개수를 계산한다.
3. 모든 셀에 같은 공통 경계와 피벗을 적용한다.
4. 프레임 인덱스를 시트 셀 좌표로 변환하는 순수 함수를 만든다.
5. 빈 마지막 셀, 한 프레임 클립, 많은 프레임과 핑퐁 끝점 중복 여부를 테스트한다.

첫 구현은 가변 크기 밀집 패킹을 사용하지 않는다. 예측 가능한 균일 그리드가 실제 엔진 적용과 오류 비교에 유리하기 때문이다.

### A4. PNG 시트와 JSON 생성

1. 기존 애니메이션 PNG 렌더러로 각 baked 프레임을 만든다.
2. 공통 경계로 정렬한 프레임을 하나의 투명 캔버스에 배치한다.
3. 같은 계산 결과로 JSON 프레임 좌표와 피벗을 작성한다.
4. 시트 PNG와 JSON을 한 번의 내보내기 명령으로 저장한다.
5. 기존 개별 프레임 ZIP과 SVG ZIP은 제거하거나 동작을 바꾸지 않는다.

### A5. 자동 검증

- 프레임 인덱스와 그리드 좌표 변환 테스트
- 루프·핑퐁 baked 순서와 메타데이터 순서 일치 테스트
- 공통 경계와 피벗이 모든 프레임에서 일정한지 검사
- 루트 이동 분리 전후에 원래 월드 동작을 재구성할 수 있는지 검사
- 시트에서 잘라낸 각 셀과 기존 PNG 프레임의 픽셀 또는 렌더 입력 일치 검사
- 잘못된 FPS, 빈 클립, 이미지 크기 한계와 파일 생성 실패 처리

### A6. 실제 파일 검증

다음 샘플을 PNG 시트와 JSON으로 내보낸다.

- 제자리 루프
- 핑퐁 재생
- 팔·다리가 셀 경계 가까이 움직이는 포즈
- `worldRotationTrack`이 있는 클립
- 루트 이동이 있는 클립
- 투명 배경과 합성 도형을 포함한 클립

시트에서 프레임을 다시 잘라 기존 ZIP 프레임과 비교하고, 간단한 외부 뷰어나 게임 엔진에서 FPS·루프·피벗·루트 이동을 재생한다. 차이가 없으면 작업 단위 A를 완료한다.

## B. 출력 표현력 확장

### B1. 재사용 가능한 튜브 단면

- 기존 팔다리 카메라 대응 면 계산을 `TubeSection` 성격의 공통 계산으로 분리한다.
- 정면·측면·45도와 원근 적용에서 기존 팔다리 출력이 변하지 않는지 먼저 회귀 검증한다.

### B2. 의상용 튜브 셸

- 부모 튜브를 감싸는 `TubeShell`에 양 끝 반지름, 길이 오프셋, 색상과 출력 그룹을 둔다.
- 소매 하나를 기준 구현으로 만들고 포즈·월드 회전·애니메이션에서 확인한다.

### B3. 출력 그룹별 병합 SVG

- 같은 출력 그룹의 원·튜브·셸·도형을 하나의 채움 경계로 병합한다.
- 내부선은 제거하고 그룹 간 경계, 카메라 거리와 레이어 순서는 유지한다.
- 편집 가이드와 선택 핸들은 병합 대상에서 제외한다.

### B4. 교차 경고

- 부분 교차를 감지해 사용자에게 알리되 첫 범위에서는 자동 깊이 절단을 하지 않는다.
- 비교차 포즈에서 외곽선 누락이나 출력 변동이 없어야 한다.

## C. 저장·애니메이션 편집 후속 이전

### C1. 브라우저 자동 저장의 v3 이전

- 기존 `Rig` 기반 캐시를 v3 프로젝트 구조로 이전한다.
- 구버전 캐시의 마이그레이션, 실패 시 보존·복구와 용량 오류 처리를 검증한다.

### C2. 여러 애니메이션 클립 선택 UI

- 프로젝트의 여러 클립을 생성·이름 변경·선택·삭제한다.
- 현재 선택 클립과 키·재생 위치가 자동 저장과 프로젝트 파일에서 복원되어야 한다.

### C3. 런타임 v3 직접 편집 범위

- 기존 호환 `Rig` 스냅샷과 v3 원본 데이터가 이중 원본이 되지 않도록 편집 소유권을 정한다.
- 전체 이전은 작은 작업 단위로 나누고 각 단계에서 기존 프로젝트 파일 호환성을 유지한다.

## D. 범용 관절·도형 구조 편집

### D1. 관절·축·면 생성과 삭제

- 빈 모델 또는 기존 모델에서 관절, 가상 관절, 축과 면을 생성·변경·삭제한다.
- 부모 순환, 중복 ID, 삭제된 참조와 퇴화 면을 방지한다.
- 각 명령은 실행 취소·다시 실행을 지원한다.

### D2. 캡슐·사각형 확장 기준

- `한쪽 방향 확장`: 현재 관절 위치를 한쪽 끝 단면 중심으로 유지하고 `+/-` 방향으로 확장한다.
- `중심 기준 대칭 확장`: 현재 관절 위치를 도형 중심으로 유지하고 길이의 절반씩 양쪽으로 확장한다.
- 모드 전환 시 `관절 위치 유지`와 `현재 도형 위치 유지`를 명시적으로 구분한다.
- 부모 연결 포트, 하위 관절 이동, 저장·복원과 실행 취소에서 선택한 기준을 유지한다.

### D3. 관계와 연결 포트

- 캡슐 끝점을 부모 연결 앵커로 선택할 수 있게 한다.
- 부모–자식과 동등 관계 생성, 역할 반전, 가상 부모 추가를 범용 UI로 제공한다.

## E. 고급 고정 출력 카메라

- 기존 `projectionStrength`를 명시적인 원근/직교 투영으로 이전한다.
- 카메라 위치, 대상, up, 수직 FOV 또는 직교 높이, near/far를 정의한다.
- 기존 프로젝트를 새 카메라로 마이그레이션해 화면 결과를 최대한 보존한다.
- `outputView`의 역할은 계속 프로젝트 고정 출력 기준이며 카메라 애니메이션은 추가하지 않는다.

## 공통 완료 원칙

- 슬라이더의 표시 범위를 저장 데이터의 임의 상한으로 사용하지 않는다.
- 편집 화면, 미리보기와 파일 출력은 가능한 한 같은 렌더 계산을 공유한다.
- 새 저장 필드는 형식 버전, 구버전 마이그레이션과 유효성 검사를 함께 추가한다.
- 기존 기능을 제거하거나 결과를 변경할 때는 자동 회귀 테스트와 실제 파일 비교를 모두 수행한다.
- 한 작업 단위의 완료 조건이 충족되기 전에는 후속 작업의 대규모 데이터 구조 변경을 섞지 않는다.
