# 현재 작업 진행 순서와 완료도

이 문서는 현재 작업의 실행 순서와 완료도를 판단하는 기준이다. 세부 설계는 다른 문서를 참고하되, 서로 충돌할 때는 이 문서의 상태와 순서를 우선한다. 정확한 시간·날짜 추정은 두지 않고 선행 조건과 검증 결과로 다음 작업을 결정한다.

## 완료된 작업 단위 — 체형·포즈 분리와 프로젝트 저장

목표는 체형의 기본 관절 배치와 포즈 변형을 분리하고, 고정된 출력 카메라를 기준으로 모델·애니메이션을 안전하게 저장·복원하는 것이다.

| 순서 | 작업 | 상태 | 확인 결과 |
| ---: | --- | --- | --- |
| 1 | 신체·포즈·외형·출력 시점의 데이터 소유권 정리 | 완료 | v3 데이터 계약과 문서 작성 |
| 2 | 기존 `Rig`와 v3 프로젝트 문서의 양방향 변환 | 완료 | 리그·신체·포즈·외형·출력 시점 변환 테스트 통과 |
| 3 | `baseOffset` XYZ와 체형 전환 보정 | 완료 | 아동체 방향, 목 길이 누적, 기본 포즈 깊이와 체형 반복 전환 누적 변형 수정 |
| 4 | 회전 중 관절 거리 계산을 XYZ로 통일 | 완료 | 관절·동등 그룹의 회전 전후 거리 유지 테스트 통과 |
| 5 | 체형 기준 내장 포즈 정리 | 완료 | T 포즈 제거, 기본 포즈 초기화·팔 내림·30° 포즈를 `baseOffset` 기준으로 적용 |
| 6 | v3 프로젝트 JSON 저장·복원 | 완료 | 현재 모델, 포즈·월드 회전·외형 애니메이션 트랙 왕복 지원 |
| 7 | 체형 독립 포즈 적용 | 완료 | 새 포즈 프리셋은 `body-relative-v3` 변화값으로 저장하며, 기존 절대 좌표 JSON은 호환 경로로 유지 |
| 8 | 실제 브라우저 파일·렌더링 왕복 점검 | 완료 | 작업 화면·저장 직전·PNG·SVG·애니메이션 ZIP 확인, 포즈·체형 JSON 개별 적용과 전체 v3 프로젝트 저장·재불러오기 성공 |

중간 관절의 3D 회전에서 하위 관절 Z가 기존 `-100~100` 범위에 잘려 연결 거리가 줄어들던 문제는 값 제한 정책 수정으로 보정했다. 관절 좌표·크기·거리 비율의 임의 상한 제거와 자동 검증, 8번 렌더링·파일 왕복 점검까지 마쳤다.

애니메이션의 회전 검증 중 부모 상대 관절 벡터를 XY로만 보간하고 Z를 시작 키에 고정하던 문제를 수정했다. 관절 연결은 부모 상대 XYZ 방향을 구면 보간해 회전만 있는 구간의 길이를 유지한다. `worldRotation`은 별도로 보간하며, 재생과 ZIP 출력에는 현재 프로젝트의 고정 `outputView`를 일관되게 적용한다.

체형 전환은 변경 직전의 포즈 방향을 기준 신체 벡터에 붙은 직교 좌표계의 성분과 XYZ 길이 비율로 보존한다. 이로써 기본 깊이가 다른 여성체·아동체를 반복 전환해도 최단 회전을 다시 추정하며 포즈가 누적 변형되지 않는다. 3D로 굽힌 팔·무릎·허리를 두고 여성체↔아동체를 4회 왕복한 좌표 일치 테스트를 추가했다.

이 작업 단위는 자동 테스트·빌드와 실제 파일 출력·재불러오기 검증을 모두 통과해 완료로 닫는다.

## 완료된 작업 단위 — 게임용 애니메이션 패키지 출력

게임 리소스 출력부터 후속 편집 확장까지의 전체 일정과 단계별 완료 조건은 [다음 작업 일정](NEXT_WORK_SCHEDULE.md)에 정리한다.

### 목표

현재의 PNG 프레임 ZIP과 동일한 보간·투영·합성 경로를 사용해, 게임 엔진에서 바로 자를 수 있는 투명 PNG 스프라이트 시트와 JSON 메타데이터를 함께 출력한다.

### 구현 순서

| 순서 | 작업 | 상태 | 완료 기준 |
| ---: | --- | --- | --- |
| 1 | 출력 계약 확정 | 완료 | 균일 그리드, 공통 경계, 피벗, 프레임 순서와 메타데이터 스키마를 문서화 |
| 2 | 스프라이트 배치 계산 | 완료 | 기존 baked 프레임 순서를 그리드 셀 좌표로 변환하는 순수 함수와 테스트 추가 |
| 3 | PNG 스프라이트 시트 생성 | 구현 완료 | 고정 `outputView`와 공통 경계를 사용한 모든 프레임이 투명 시트에 순서대로 배치 |
| 4 | JSON 메타데이터 생성 | 구현 완료 | FPS, 재생 방식, 프레임 인덱스·좌표·크기·지속 시간, 이미지 크기, 공통 피벗·루트 이동 기록 |
| 5 | 내보내기 UI와 패키지 | 구현 완료 | 시트 PNG와 JSON을 한 번의 명령으로 저장하고 기존 프레임 ZIP 출력은 유지 |
| 6 | 출력 피벗 직접 설정 | 구현 완료 | 자동/수동 피벗, 선택 관절 프레임별 추적, 모든 셀의 정확한 중앙 정렬, 캔버스 드래그·수치 입력·자동 복귀를 지원 |
| 7 | 실제 파일 검증 | 완료 | 실제 PNG·JSON, 선택 관절 피벗 중앙 정렬, Unity 임포트와 외부 재생을 확인했다. 육안상 픽셀 단위의 미세 흔들림은 현재 최소 기준을 막지 않는 편차로 수용 |

### 출력 규칙

- 첫 범위는 패킹 효율보다 예측 가능한 **균일 그리드**를 사용한다. 모든 셀은 같은 크기와 공통 경계를 가진다.
- 프레임 순서와 루프·핑퐁 확장 규칙은 기존 `bakePoseClipFrames()` 결과를 그대로 재사용한다.
- JSON의 `sequence.kind: "baked-cycle"`은 `frames` 배열이 이미 루프 또는 핑퐁 한 주기를 포함함을 뜻한다. 외부 런타임은 배열을 다시 왕복시키지 않고 순서대로 재생한 뒤 0번 인덱스로 반복한다.
- 시트 생성은 기존 렌더러를 바꾸지 않고 프레임 출력을 하나의 캔버스에 배치하는 패키징 단계로 추가한다.
- 현재 자동 피벗은 기준 프레임의 가슴 X와 전체 프레임의 발목 최하단 Y를 사용한다. 좌우 대칭 여백은 자동 맞춤 뷰어에서 차이가 거의 보이지 않으므로 최종 배치 기준으로 강제하지 않는다.
- `outputView`에 자동/수동 출력 피벗을 추가했다. 직접 이동·수치 입력 피벗은 고정 출력 좌표를 사용하고, 선택 관절에 맞춘 피벗은 관절 ID를 저장해 프레임마다 위치를 다시 계산한다.
- 선택 관절 추적은 관절의 화면용 도형 표시 여부와 무관하게 관절 월드 좌표를 직접 투영한다. 기본체의 숨김 `head` 관절과 이를 따르는 머리 아트 도형을 실제 시트로 출력해 각 셀 중앙 정렬을 확인했다.
- 각 프레임은 계산된 피벗이 셀의 정확한 X/Y 중앙에 오도록 개별 출력 경계를 이동한다. 공통 셀 크기는 피벗 기준 최대 범위로 한 번만 계산한다.
- 프레임별 몸통 흔들림은 다시 정렬하지 않고 유지하며, 루트 이동은 이미지에서 제거해 메타데이터에 분리한다.
- 카메라 애니메이션은 추가하지 않고 프로젝트의 고정 `outputView`와 클립의 `worldRotationTrack`을 사용한다.

외부 재생에서 약간의 흔들림이 관찰됐지만 픽셀 단위의 작은 범위이며 에셋 사용을 막지 않아 현재 출력 최소 기준에서는 허용한다. 흔들림이 확대되거나 실제 배치 오차를 만들면 피벗 반올림과 프레임 경계 계산의 회귀 사례로 다시 승격한다.

## 현재 작업 단위 — 렌더링 보정과 신체 확장 의상

상세 순서와 완료 조건은 [신체 확장 의상과 렌더링 최소 일정](GARMENT_RENDERING_SCHEDULE.md)과 [렌더링 및 의상 통합 작업 일정](RENDERING_COSTUME_WORK_SCHEDULE.md)을 따른다.

### 현재 및 후속 순서

1. **렌더링 보정과 신체 확장 의상 — 진행 중**
   - 외곽선과 원근 회전 출력을 먼저 보정한다.
   - 원·타원·원호 기반 튜브 단면을 비교하고, 시점 안정성·절단 캡·의상 두께·SVG 병합을 기준으로 1차 방식을 정한다.
   - 허리·골반 측 관절 외곽을 경계로 전이 다각형을 생성하고, 내부 채움·분할·병합 방식은 비교 표본 뒤 결정한다.
   - 어깨 아래에서 이어지는 둥근 사각형 기반 갈비뼈·흉곽 외곽을 허리 단면으로 연결하고, 측면 실루엣과 내부 패치 방식을 검토한다.
   - 머리 구에 연결된 기본 얼굴 면과 눈·코·입 배치 기준을 추가해 캐릭터 기본 표면을 완성한다.
   - 원본 관절·튜브를 유지하는 가이드/출력 분리, 의상 가림, 관절 단위 튜브 셸과 로컬 축 절단을 구현한다.
   - 상세 순서와 완료 조건은 [신체 확장 의상과 렌더링 최소 일정](GARMENT_RENDERING_SCHEDULE.md)을 따른다.
2. **저장·편집 후속 이전**
   - 브라우저 자동 저장을 v3 구조로 이전한다.
   - 여러 애니메이션 클립 선택 UI와 런타임의 v3 직접 편집을 별도 작업 단위로 진행한다.
3. **범용 관절 편집 확장**
   - 관절·축·면 생성·삭제 UI와 캡슐·사각형의 한쪽/중심 대칭 확장 기준을 구현한다.
4. **고급 출력 카메라 — 후속 작업**
   - 현재 `projectionStrength`를 FOV, 카메라 위치·대상, near/far와 직교 출력 범위로 교체한다.
   - `outputView`는 계속 프로젝트 고정값으로 유지하며 카메라 애니메이션은 만들지 않는다.

## 고정 결정

- 애니메이션 결과는 프로젝트의 고정 `outputView`에 비치는 상을 기준으로 한다.
- 카메라 애니메이션과 `ViewTrack`은 만들지 않는다.
- 캐릭터 전체 회전이 필요하면 포즈 트랙과 분리된 `worldRotationTrack`을 사용한다.
- 체형의 기본 자세는 각 체형의 `baseOffset`이며, 공통 T 포즈를 강제하지 않는다.
- 정확한 일정 시간보다 재현 가능한 완료 조건과 실제 출력 결과를 우선한다.
