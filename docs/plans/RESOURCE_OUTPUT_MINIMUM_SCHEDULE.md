# 리소스 출력 최소 기능 구현 일정

## 목표와 범위

목표는 편집 중인 분리 도형 리그로부터, 게임 리소스로 사용할 수 있는 **깨끗한 그룹 단위 SVG**를 안정적으로 출력하는 것이다. 첫 번째 범위는 아래 세 가지를 끝까지 연결한다.

1. 기본 3D 회전은 현재 카메라 기준으로 수행하고, 애니메이션 재생·내보내기에도 같은 변환과 투영을 적용한다.
2. 팔다리 튜브 위에 의상용 튜브 셸을 올리고, 카메라 방향에 맞는 단면 실루엣을 그린다.
3. 출력 시 그룹 안의 면을 합쳐 내부선을 제거하고, 그룹 간 경계만 남긴 SVG를 만든다.

정밀한 교차 절단 렌더러나 모든 의상 편집 도구는 이 일정의 완료 조건이 아니다.

## 예상 소요

집중 개발 기준 **8~10일**(검증 포함)이다. 외부 Boolean path 라이브러리를 새로 도입하거나, 실제 에셋에서 복잡한 교차 사례가 발견되면 병합 출력 단계에 1~2일을 추가한다.

| 단계 | 소요 | 선행 조건 | 완료 산출물 |
| --- | ---: | --- | --- |
| M0. 계약·회귀 기준 확정 | 1일 | 없음 | 데이터 경계, 카메라 회전 조작 규칙, 테스트 포즈 |
| M1. 카메라 기준 회전·애니메이션 프레젠테이션 분리 | 1.5일 | M0 | 카메라 회전 조작과 동일한 재생·프레임 출력 |
| M2. 일반 튜브와 의상 셸 | 2~3일 | M1 | 팔/다리용 튜브 셸, 최소 속성 UI, 회전 대응 단면 |
| M3. 그룹 병합 SVG 출력 | 2~3일 | M2 | 내부선 없는 그룹별 SVG path 출력 |
| M4. 통합 검증·교차 경고 | 1~1.5일 | M3 | 회귀 세트, 교차 감지 경고, 에셋 샘플 |

## 단계별 작업

### M0 — 계약·회귀 기준 확정 (반나절)

- 포즈 데이터와 표시 데이터의 경계를 고정한다. 관절 `x/y/z`, 로컬 회전, 반지름은 포즈이고, 월드 방향·시점 회전·원근 값은 프레젠테이션이다.
- 기본 회전은 카메라 기준으로 정한다. 화면 가로 드래그는 현재 카메라의 위쪽 축, 세로 드래그는 카메라의 오른쪽 축을 중심으로 누적해 어느 시점에서도 화면 기준으로 자연스럽게 돈다. 필요할 때 카메라 정면축 회전(roll)도 같은 카메라 기준으로 처리한다.
- 월드 X/Y/Z 축 회전은 기본 드래그에 섞지 않는다. **축 고정 수정 키**를 누른 상태에서만 진입하는 별도 모드로 두고, 축 선택·스냅·슬라이더는 이 모드의 보조 수단으로 처리한다. M0에서 기존 단축키와 충돌하지 않는 정확한 수정 키를 확정한다.
- 누적 카메라 회전은 내부적으로 방향 합성이 가능한 표현(쿼터니언 또는 동등한 회전 행렬)을 기준으로 하고, 패널의 X/Y/Z 수치는 월드 축 모드용 입력·표시값으로만 변환한다. 기존 `worldRotation` 데이터는 호환 변환을 제공한다.
- `TubeSection`, `TubeShell`, `ExportGroup`의 저장 형식과 기본값을 [그래픽 생성 사양](../../GRAPHICS_GENERATION_SPEC.md)에 맞춰 확정한다.
- 정면·측면·45도, T 포즈·팔 내림·다리 교차의 고정 리그를 회귀 입력으로 저장한다.

**완료 기준:** 각 입력의 편집 화면 PNG/SVG와 기대되는 그룹·외곽선 규칙을 비교할 수 있다.

### M1 — 카메라 기준 회전과 애니메이션 프레젠테이션 일치 (1.5일)

- 기본 우클릭/탐색 드래그와 터치 제스처를 카메라 기준 회전으로 바꾼다. 드래그 중 두 축을 동시에 합성할 수 있으며, 카메라를 돌린 뒤에도 화면 가로·세로의 의미가 유지돼야 한다.
- 월드 축 모드는 M0에서 정한 수정 키를 누를 때만 활성화한다. 이때에만 X/Y/Z 축 고정, 축별 슬라이더와 각도 스냅을 우선하며, 기본 카메라 회전과 혼동되지 않게 안내 문구·축 가이드를 갱신한다.
- 키 보간은 관절의 `z`를 `x/y`와 같이 보간한다.
- `renderPoseSample(sampledPose, presentation)` 경로를 만들고, 편집 미리보기·재생·애니메이션 내보내기가 모두 이 경로를 사용하게 한다.
- 키 저장·수정은 월드 회전·원근 값을 바꾸지 않는다. 시점 애니메이션은 별도 `ViewTrack`이 필요해질 때까지 만들지 않는다.

**완료 기준:** 같은 프레임은 정지 편집 화면, 재생 중 화면, PNG/SVG 프레임 출력에서 같은 카메라 기준 회전·투영 결과를 가진다. 기본 드래그는 카메라 기준으로 누적되고, 수정 키를 누를 때만 월드 X/Y/Z 축 모드가 활성화된다. 어느 조작도 포즈 키 값을 오염시키지 않는다.

### M2 — 일반 튜브와 의상 셸 (2~3일)

- 기존 팔다리의 카메라 대응 면 생성을 일반적인 `TubeSection` 두 개의 실루엣 계산으로 분리한다.
- `TubeShell`은 부모 튜브를 참조하고 시작·끝 단면의 반지름/오프셋/길이만 독립 조정한다.
- 첫 UI는 선택한 튜브에 대한 셸 추가·삭제, 양 끝 반지름, 길이 오프셋, 색상, 출력 그룹만 제공한다. 소매 한 종류를 기준 구현으로 한다.
- 월드 회전과 원근 아래에서도 몸통·팔과 같은 방식으로 카메라 방향 단면이 갱신되도록 한다.

**완료 기준:** 팔 위에 소매 셸 하나를 만들고, 정면·측면·45도 및 애니메이션 프레임에서 평면으로 꺾이지 않는 실루엣을 확인할 수 있다.

### M3 — 그룹 병합 SVG 출력 (2~3일)

- 출력 전 모든 원·튜브·셸을 투영하고, `ExportGroup`별로 수집한다.
- 같은 출력 그룹의 면은 Boolean union으로 하나의 채움 path로 만든다. 그룹 내부 경계와 내부선은 출력하지 않는다.
- 그룹 사이 경계는 `outlinePolicy`에 따라 외곽선 또는 보존 경계로 출력하고, 카메라 거리 순서대로 정렬한다.
- 편집용 분리 SVG와 출력 SVG를 분리한다. 편집 조작점·선택 표시·보조선은 절대 결과물에 포함하지 않는다.

**완료 기준:** 몸통, 한 팔, 한 소매가 각각 지정한 출력 그룹으로 병합되어 내부선 없이 SVG로 내려받아지고, 다른 SVG 뷰어에서도 같은 모양으로 열린다.

### M4 — 통합 검증과 교차 경고 (1~1.5일)

- M0 회귀 포즈를 편집 화면·정지 SVG·애니메이션 SVG/PNG로 비교한다.
- 튜브/셸의 부분적인 앞뒤 교차를 감지해 경고한다. 이 단계에서는 자동 절단하거나 깊이 버퍼를 구현하지 않는다.
- 실제 게임 에셋 한 개를 출력해 파일 크기, path 수, 외곽선 누락, 색상·투명 배경을 확인한다.

**완료 기준:** 알려진 교차는 경고되며, 비교차 포즈는 내부선·보조선·누락된 외곽선 없이 반복 출력된다.

## 이번 최소 범위에서 미루는 작업

- 링의 8~12개 정점을 샘플링해 부분 교차를 절단하는 세부 깊이 렌더러
- 머리·목·의상 사이처럼 한 그룹 내부에서도 앞뒤가 바뀌는 영역의 자동 분할
- 카메라/월드 회전을 키프레임으로 기록하는 `ViewTrack`
- 여러 겹 의상, 임의의 메시 의상, 완성형 의상 편집 UI
- 편집 화면에서도 병합된 결과만 보여 주는 실시간 합성 보기

이 항목들은 M4에서 실제 에셋 제작을 막는 사례가 확인될 때만 다음 일정으로 올린다. 현재는 교차 경고와 분리 편집 상태를 유지하는 편이 비용 대비 안전하다.

## 결정 지점

- **M1 종료:** 카메라 기준 회전과 월드 축 모드의 입력 규칙, 그리고 이들이 포즈가 아닌 프레젠테이션이라는 규칙을 고정한다.
- **M2 종료:** 튜브 셸만으로 소매·바지 같은 첫 의상을 표현할 수 있는지 실제 에셋으로 평가한다.
- **M4 종료:** 부분 교차가 빈번하면 정밀 깊이 렌더러를 다음 최우선 작업으로 승격한다. 그렇지 않으면 스프라이트 시트·프로젝트 저장 등 기존 에셋 제작 흐름으로 돌아간다.
