# 범용 관절 기반 편집 도구 기능 정리

> **범위:** 이 문서는 사람뿐 아니라 동물, 기계, 소품 등 다양한 관절 기반 대상을 만들기 위한 범용 편집기의 기능, 장기 백로그와 저장 요구사항을 정리한다. 기본 인체는 범용 기능으로 구성하는 하나의 예시다. 현재 활성 작업은 [예정 작업 목록](README.md)과 개별 계획 문서를 기준으로 한다.

## 1. 목표와 원칙

- 특정 관절 이름, 좌우 개수, 인체의 형태나 계층을 전제하지 않고 새 대상의 구조를 만들고 편집한다.
- 관절, 축, 면, 관계, 가상 관절과 도형은 모델 데이터로 정의한다. 개별 모델의 이름을 코드에서 특별 취급하지 않고 같은 규칙으로 처리하는 것이 목표다.
- 기본 인체의 골반 중심과 어깨 관계는 예시이며, 가상 부모와 동등 관계는 범용 편집기에 정식으로 포함할 기능이다. 골반 전용 기능이나 임시 우회로 취급하지 않는다.
- 편집 가이드와 실제 출력물을 분리한다. 가상 관절은 변환과 조작에 사용하며 그 자체를 출력용 도형으로 강제하지 않는다.
- 이동·회전·비율·저장 시 어떤 요소에 영향이 전달되는지 예측 가능해야 한다. 관계 변경은 가능한 한 기존 화면상 포즈를 유지하고 실행 취소할 수 있어야 한다.
- 기존 문서의 인체 전용 예시나 오래된 구현 설명이 범용 요구사항을 제한하지 않는다. 상세 렌더 규칙은 [그래픽 생성 사양](../GRAPHICS_GENERATION_SPEC.md), 현재 동작과 인계 사항은 [프로젝트 인계 문서](../PROJECT_HANDOFF.md)를 참고한다.

## 2. 데이터 구성

| 요소 | 역할과 범용 요구사항 | 현재 상태 |
|---|---|---|
| 모델/장면 | 여러 관절과 아트 요소를 담는 작업 대상. 기본 인체는 프리셋 중 하나로 취급 | 기본 인체 편집만 제공. 빈 모델 생성과 임의 모델 구성 UI는 미구현 |
| 관절 | 위치, 크기, 로컬 회전, 축, 표시와 계층을 가진 편집 대상 | 기본 관절의 속성 편집 가능. 임의 추가·삭제 UI는 미구현 |
| 축과 연결점 | 관절별 독립 축과 활성 끝점. 면이 관절·축·방향을 참조 | 데이터와 편집 지원. 현재 축 수 제한은 정책값이며 임의 축 추가 UI는 미구현 |
| 면 | 여러 연결점을 참조하는 다각형. 연결점 변화에 따라 형상 갱신 | 기본 면 편집·표시 지원. 임의 생성·정점 편집 UI는 미구현 |
| 일반 도형/아트 | 관절·면에 연결하거나 독립 배치할 그림 요소 | 향후 기능. 현재 큰 머리 원은 임시 미리보기 |
| 부모·자식 관계 | 부모 변환을 자식과 하위 계층에 전달 | 부모 변경과 순환 방지 지원 |
| 동등 관계 | 둘 이상의 관절을 관계 그룹으로 관리하고 공통 회전 조작 제공 | 기본 어깨·골반 그룹 구현. 임의 생성·편집 UI는 미구현 |
| 가상 관절 | 출력에 나타나지 않는 위치·회전 기준 또는 관계 연결점 | 기본 골반 가상 부모와 두 동등 관절의 가상 부모 추가 지원. 독립적인 범용 생성·편집은 미완성 |
| 그룹·레이어 | 표시와 렌더 순서를 관리하는 별도 분류 | 그룹 및 항목 순서·표시 편집 지원 |

관절 간 변환 계층, 동등 관계와 레이어 그룹은 서로 다른 개념이다. 레이어 그룹이 같다는 이유로 변환을 상속하거나 동등 관계가 되지 않는다.

## 3. 관계와 가상 부모

### 3.1 부모·자식과 동등 관계

- 부모가 이동·회전하면 자식의 로컬 변환을 통해 하위 계층이 따라간다. 부모를 변경할 때는 새 로컬 좌표를 계산해 화면상 위치와 회전을 유지한다.
- 동등 관계는 공통 조작을 나타내며 그 자체가 부모·자식 관계를 만들지는 않는다. 그룹 회전은 정의된 중심과 회전 대상을 사용한다.
- 관계의 생성·변경·삭제는 유효한 참조를 유지하고 순환 부모 관계, 중복 ID 및 없는 관절 참조를 막아야 한다.
- 축의 정렬 기준과 변환 부모는 구분할 수 있어야 한다. 부모를 바꾸더라도 면 연결에 필요한 축 기준이 의도치 않게 바뀌지 않아야 한다.

### 3.2 두 동등 관절의 가상 부모 추가

이 기능은 특정 신체 부위가 아닌 **두 동등 관절에 적용하는 범용 편집 명령**이다.

1. 두 관절로 구성된 동등 그룹의 구성원을 선택하고 가상 부모 추가를 실행한다.
2. 두 관절의 중심 위치에 출력되지 않는 가상 관절을 만들고, 두 관절을 그 자식으로 연결한다.
3. 생성 전후에 두 관절과 그 하위 계층의 화면상 위치·회전이 유지되도록 로컬 변환을 재계산한다.
4. 동등 관계의 회전 중심을 가상 부모와 연결한다. 가상 부모를 이동·회전하면 자식 계층은 일반 부모 규칙에 따라 움직인다.
5. 생성과 관계 변경은 한 번에 실행 취소·다시 실행할 수 있어야 하며 기존 참조와 저장 데이터의 호환성을 검사한다.

**현재 제한:** 추가 버튼은 두 관절의 부모가 같을 때만 활성화되며, 같은 그룹에 이미 가상 부모가 있으면 중복 생성하지 않는다. 서로 다른 부모를 가진 두 관절, 3개 이상의 동등 관절, 이미 존재하는 관절을 가상 중심으로 연결하는 편집 방식은 아직 정해지거나 구현되지 않았다. 공통 부모 선택, 기존 포즈 보존, 변환 상속과 축 정렬을 정의한 뒤 범용화해야 한다.

### 3.3 기본 인체 적용 예시

현재 기본 인체에서는 `pelvis-pivot`이 허리와 양쪽 골반의 공통 가상 부모다. 허리를 움직이면 가슴과 팔 등 허리 하위 계층은 따라가고, 양쪽 골반과 다리는 그 자리에 남는다. 골반 그룹을 회전하면 가상 부모와 그 아래의 허리·양쪽 골반이 함께 회전한다. 이 구조는 기본 모델 데이터의 선택이며 모든 모델에 허리나 골반이 있어야 한다는 의미가 아니다.

## 4. 편집과 조작

### 현재 제공하는 기능

- 관절과 면 선택, Shift 다중 선택, 사각 선택, 선택 관절의 이동·다중 회전.
- 관절의 화면상 위치·반지름, 부모, 축 각도 편집 및 관련 관절 사이의 거리 입력. 부모·자식 거리는 한쪽 하위 트리를 이동하며, 두 관절 동등 그룹의 중심 간격은 중점을 유지한 채 양쪽을 대칭 이동한다.
- 두 관절 동등 그룹의 가상 중심은 동등축 방향 X와 직교 방향 Y 오프셋으로 조정한다. 오프셋 변경 시 현재 포즈는 유지되고 이후 그룹 회전의 피벗에 반영된다.
- 비율 유지 체크박스 또는 Alt 드래그를 통한 부모 거리 유지. 여러 관절 선택에서는 현재 구현된 다중 선택 규칙을 따른다.
- 동등 그룹 회전 핸들, 레이어 및 그룹 순서 변경, 단색 칠하기와 팔레트, 관절 출력 표시 설정.
- 실행 취소·다시 실행, 확대·축소, 화면 이동, 조작 안내 창.

### 범용 편집에 필요한 기능

- 빈 작업에서 관절·축·관계·연결점·면을 생성, 변경, 삭제하고 이름과 안정적인 ID를 관리한다. 관절·축·면 추가는 아래와 같이 범용 도구의 정식 기능이다.
- 가상 관절의 생성·선택·이동·관계 편집을 지원하고, 사용자가 무엇이 함께 이동하는지 확인할 수 있게 한다. 동등 그룹의 중심 오프셋 편집은 자식의 현재 포즈를 보존하는 피벗 재배치로 구현했으며, 일반 관절 이동은 기존처럼 하위 계층이 따라간다.
- 동등 그룹의 구성원과 회전 기준을 편집한다. 가상 부모 삽입이나 관계 변경으로 기존 면, 축 정렬, 선택 및 실행 취소가 깨지지 않아야 한다.
- 연결 거리 및 비율 유지의 기준과 이동 대상을 관계별로 명확히 표시한다. 상충하는 거리 제약, 0거리, 순환 또는 불가능한 제약을 처리하는 방식은 별도 설계가 필요하다.
- 축 수, 관절 크기·개수, 연결 대상 등을 고정된 인체 이름에 묶지 않는다. 현재 제한과 정책을 사용자에게 알리고 확장 가능하게 한다.

### 4.1 관절 추가 — 정식 기능, 미구현

- 빈 모델이나 기존 모델에 관절을 추가하고 위치, 크기, 이름과 고유 ID를 지정할 수 있어야 한다. 배치한 뒤에도 기존 관절과 같은 방식으로 선택·이동·회전 및 속성 편집이 가능해야 한다.
- 부모 없이 독립적으로 추가하거나 기존 관절을 부모로 지정할 수 있어야 한다. 부모·자식과 동등 관계는 추가 후에도 편집 가능해야 하며 순환 관계는 허용하지 않는다.
- 일반 관절과 출력에 나타나지 않는 가상 관절을 구분해 생성할 수 있어야 한다. 가상 관절은 다른 관절의 부모나 회전 기준으로 사용할 수 있다.
- 관절에는 필요에 따라 축을 추가하고 출력 표시, 색상, 그룹과 레이어를 설정할 수 있어야 한다. 생성 시 기본값과 구체적인 배치 조작은 이후 UI 설계에서 정한다.
- 추가·변경·삭제는 실행 취소와 다시 실행을 지원해야 한다. 관절을 참조하는 면이나 관계가 있을 때 삭제 정책은 사용자가 알 수 있어야 하며, 자동 삭제·연결 해제 등 구체적인 처리 방식은 미정이다.

### 4.2 축 추가 — 정식 기능, 미구현

- 선택한 관절에 축을 추가하고 관절 내 고유 ID, 각도 및 사용할 끝점을 지정할 수 있어야 한다. 축은 관절 중심과 반지름을 공유하지만 각 축의 각도와 끝점 사용 여부는 독립적이다.
- 각 끝점은 면의 연결점으로 사용할 수 있어야 하며, 관절 이동·크기 변경이나 축 회전 시 이를 참조하는 면이 함께 갱신되어야 한다.
- 자동 정렬이 필요한 축은 관계 기준과 정렬 방식을 지정할 수 있어야 한다. 직접 각도를 편집하는 축과 자동 계산되는 축은 구분해 표시한다.
- 현재 기본 정책인 관절당 최대 3개는 범용 도구의 고정적인 한계로 간주하지 않는다. 모델 또는 편집 정책별 제한과 이를 바꾸는 UI는 추후 설계한다.
- 축 추가·변경·삭제는 실행 취소가 가능해야 한다. 이미 면이 참조하는 축이나 끝점의 삭제·비활성화는 참조가 끊기지 않도록 확인과 처리 정책이 필요하다.

### 4.3 면 추가 — 정식 기능, 미구현

- 여러 관절의 축 끝점을 순서대로 지정해 연결 면을 추가할 수 있어야 한다. 면의 꼭짓점은 화면 좌표가 아니라 관절 ID·축 ID·끝점 방향을 참조한다.
- 생성한 면은 참조하는 관절·축을 움직일 때 함께 변형되어야 하며, 꼭짓점 순서와 연결 관계를 편집할 수 있어야 한다. 삼각형·사각형을 포함한 다각형을 다룰 수 있어야 한다.
- 면의 색상 또는 팔레트, 그룹, 레이어와 회전 대상을 설정할 수 있어야 한다. 부모·자식 또는 동등 관계의 회전 대상을 선택하는 방법과 회전 대상이 없는 면의 처리 방식은 추후 설계한다.
- 면을 만들거나 수정할 때 존재하지 않는 관절·축·비활성 끝점을 참조하지 않아야 하며, 부족한 꼭짓점이나 중복·퇴화·자기 교차 등 유효성 검사의 세부 정책을 사용자에게 안내해야 한다.
- 면 추가·변경·삭제는 실행 취소와 다시 실행이 가능해야 한다. 생성 UI와 정점 선택·편집 조작은 아직 구현되지 않았다.

## 5. 외형·레이어·출력

- **현재:** 기본색, 팔레트와 관절·면별 색상, 표시 설정, SVG/PNG 출력과 미리보기를 제공한다. 같은 색의 팔레트 병합과 팔레트 변경의 연결 색상 반영을 지원한다.
- **현재 순서 규칙:** 최종 렌더 순서는 그룹 값과 관절·면의 개별 레이어 값을 합산한다. 그룹을 앞으로 옮겨도 항목별 값 때문에 다른 그룹과 순서가 섞일 수 있다.
- **향후:** 자유 도형, 관절·면 바인딩, 텍스처와 외부 에셋 참조를 지원한다. 그리기·바인딩·변형 방법과 관절별 깊이 충돌 처리는 별도 설계가 필요하다.
- 편집 가이드, 가상 관절, 선택 핸들은 출력에 포함하지 않는다. 화면·미리보기·출력에서 실제 아트의 순서와 표시가 일치해야 한다.

### 5.1 여러 모델과 선택 — 향후 기능

- 한 장면에 여러 모델을 추가하고 활성 모델을 전환해도 각 모델의 포즈·비율·색상과 편집 기록이 서로 덮어쓰이지 않아야 한다.
- 장면 상태와 모델 내부 리그 상태를 분리하고, 이동·크기·렌더 순서 같은 장면 변환은 모델의 로컬 관절값을 직접 변경하지 않는다.
- 프리셋을 다른 모델에 적용할 때는 관절 대응과 계층 호환성을 검사하고, 대상 비율을 유지할지 프리셋 비율을 적용할지 선택하게 한다.

### 5.2 자유 도형·텍스처와 바인딩 — 향후 기능

- 얼굴형, 머리카락, 옷과 장식은 리그 연결 면과 분리된 `ArtShape`로 추가·편집·삭제한다.
- 첫 단계는 관절 하나에 묶인 도형의 이동·회전이며, 이후 두 관절이나 면을 따르는 가중치 바인딩과 삼각형·barycentric 좌표로 확장한다.
- 외부 이미지는 프로젝트 에셋으로 식별하고 절대 경로에 의존하지 않는다. 누락된 에셋은 알리고 재연결할 수 있어야 한다.
- 편집용 SVG, 최종 Canvas/WebGL 렌더와 PNG/SVG 출력은 같은 변형 좌표와 순서 결과를 사용한다.

### 5.3 유사 3D와 깊이 파라미터 — 보류

- 유사 3D는 실제 3D 메시 회전이 아니라, 시점별로 작성한 2D 기준 형상 사이를 보간하는 방식이다. 포즈 편집과 `viewAngle`은 분리한다.
- 관절과 관절에 연결된 외형 도형에는 `depth` 파라미터를 둘 계획이다. 이 값은 시점 회전에서 위치·크기·관절 간 화면상 거리 및 깊이 순서가 얼마나 변형되는지 조절하는 값이며, 실제 3D 좌표를 복원한다고 주장하지 않는다.
- `depth`는 기준 형상, 시점별 정점 보정, 표시 상태와 레이어 보정을 보조한다. 얼굴 실루엣·가려짐·측면 전용 파츠처럼 자동 원근만으로 표현할 수 없는 변화는 기준 형상에서 직접 작성한다.
- 값의 범위와 부호, 관절 간 거리·반지름·정점에 적용하는 수식은 정면↔한쪽 측면 프로토타입을 만든 뒤 확정한다. 기본 포즈에 값을 누적 적용하지 않고 매 렌더마다 계산한다.

## 6. 사용자 지정 작업공간 레이아웃 — 향후 기능

- 사용자가 도구, 속성, 보간 타임라인과 향후 추가되는 패널의 크기·표시 여부·접힘 상태를 조절할 수 있게 한다.
- 패널은 허용된 왼쪽·오른쪽·하단 영역 사이에서 이동하거나 같은 영역 안에서 순서를 바꿀 수 있게 하되, 캔버스의 최소 작업 크기와 패널별 최소·최대 크기를 보장한다.
- 데스크톱, 태블릿과 모바일은 사용 가능한 배치 방식이 다르므로 화면 등급별 레이아웃을 별도로 저장한다. 넓은 화면의 배치를 모바일에 그대로 축소해 적용하지 않는다.
- `기본 레이아웃으로 초기화`와 용도별 레이아웃 프리셋을 제공한다. 잘못된 저장값이나 사라진 패널이 있어도 항상 접근 가능한 기본 배치로 복구할 수 있어야 한다.
- 작업공간 레이아웃은 프로젝트의 포즈·도형·색상 데이터와 분리된 사용자 UI 설정이다. 패널 조정은 프로젝트 실행 취소 기록에 포함하지 않으며 기본적으로 프로젝트 파일에도 저장하지 않는다.
- 마우스 드래그뿐 아니라 키보드로 크기와 위치를 조정할 수 있어야 하며, 레이아웃 변경 중 캔버스 좌표·선택 상태·편집 중인 값이 바뀌지 않아야 한다.

## 7. 저장·불러오기와 호환성

- **현재:** JSON 프리셋으로 포즈·비율·색상을 저장하고 불러올 항목을 선택할 수 있다. 전체 인물/구조 저장은 아직 지원하지 않는다.
- 현재 파일은 관절 계층 정보로 호환성을 검사한다. 계층이 다른 구조에는 포즈·비율 적용이 제한될 수 있으며, 색상만 선택한 경우에는 별도로 적용할 수 있다. 이전 기본 인체의 일부 골반 계층 형식에는 변환 처리가 있다.
- **향후:** 관절·축·관계·가상 관절·면·도형·레이어·아트 참조를 포함한 모델 전체 저장과 복원을 지원한다. 참조하는 에셋이 없을 때는 누락을 알리고 재연결할 수 있어야 한다.
- 서로 다른 모델에 포즈 또는 비율을 선택 적용하려면 관절 대응, 계층·축 호환성, 누락 항목, 대상 비율 보존 방식을 별도로 정의해야 한다. 구조가 같지 않다고 좌표를 무조건 대입하지 않는다.
- 전체 프로젝트 형식은 명시적인 버전과 압축 방식을 식별해야 하며 기존 JSON v1 프리셋을 계속 읽을 수 있어야 한다.
- 전달 형식 후보는 사람이 확인하기 쉬운 비압축 JSON, JSON을 gzip 등으로 압축한 전용 파일, 압축 결과를 Base64와 형식 접두어로 감싼 클립보드 텍스트다. 확장자 자체를 압축 기능으로 취급하지 않으며 실제 작업 데이터 크기와 브라우저 호환성을 측정한 뒤 하나 이상을 선택한다.
- 텍스처 등 외부 에셋은 안정적인 식별자·이름·선택적 내용 해시로 참조한다. 공유 시 에셋을 함께 포함할지 별도 전달할지 프로젝트 형식에서 명시하고, 누락·동일 이름 충돌·변경 감지와 재연결 정책을 제공한다.
- 압축, 파일 저장과 클립보드 복사는 같은 직렬화 데이터에 대한 운반 방식으로 분리한다. 전달 방식이 달라도 불러오기 검증과 마이그레이션 결과가 같아야 한다.
- 오프라인 설치형 앱을 제공할 경우 앱 셸과 정적 에셋을 캐시하고, 네트워크 없이 편집·프로젝트 열기·PNG/SVG 출력이 가능해야 한다. 새 배포본은 작업을 잃지 않는 업데이트 흐름을 제공한다.

## 8. 장기 구현 순서

활성 보간 기능과 반응형 레이아웃 이후의 후보 순서다. 각 항목은 앞 단계의 데이터와 검증이 안정된 뒤 시작한다.

1. 사용자 지정 작업공간 레이아웃과 화면 등급별 저장·초기화
2. 관절·축·면의 생성·삭제와 참조 무결성 UI
3. 자유 다각형 `ArtShape`와 단일 관절 바인딩
4. 여러 모델을 포함하는 장면과 모델 선택
5. 프로젝트 전체 저장, 에셋 참조와 클립보드 전달
6. 관절/면 가중치 바인딩과 삼각형 기반 변형
7. 깊이 충돌과 관절별 면 앞뒤 관계
8. 오프라인 설치형 앱
9. 정면·측면 기준 형상을 사용하는 유사 3D 시점 보간

이 순서는 기능 의존성을 나타내며 일정 확정이 아니다. 현재 우선순위는 [예정 작업 목록](README.md)을 따른다.

## 9. 범용화 검증 기준

- 기본 인체 외에 이름과 개수, 계층이 다른 관절 구조를 만들고 같은 편집 규칙으로 조작할 수 있다.
- 빈 작업에서 관절을 추가하고 축과 끝점을 지정한 뒤, 그 끝점을 연결해 면을 추가할 수 있다. 관절·축 수정 시 면이 함께 갱신되고 각 생성 작업을 실행 취소·다시 실행할 수 있다.
- 동등 관절 두 개에 가상 부모를 추가해도 화면상 포즈가 유지되며, 생성·회전·이동·실행 취소와 다시 실행이 일관되게 동작한다.
- 가상 부모의 영향을 받는 관절과 받지 않는 관절이 모델 데이터의 관계에 따라 결정된다. 특정 관절 ID에 의존한 분기가 결과를 바꾸지 않는다.
- 부모 변경·동등 회전 이후 면 연결과 축 정렬이 유지되고, 사용자 선택과 내보내기 결과가 정상이다.
- 같은 구조의 저장·복원은 포즈와 비율을 보존한다. 다른 구조나 누락된 에셋은 자동으로 잘못 적용하지 않고 사용자에게 알려야 한다.
- 브라우저에서 실제 선택·드래그·다중 선택·저장 및 출력 조작을 확인한다. 현재 자동 테스트만으로 브라우저 시각과 조작 품질을 보증하지 않는다.
