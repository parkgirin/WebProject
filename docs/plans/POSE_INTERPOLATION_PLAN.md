# 포즈 키프레임 보간 계획

> **상태: 구현 진행 중.** 이 계획은 리그의 자세를 여러 키프레임으로 저장하고 재생 위치에 따라 보간하는 기능을 정의한다. 포즈와 월드/카메라 프레젠테이션 변환은 서로 다른 소유 데이터로 유지한다.

## 0. 현재 진행 상태

- 구현됨: `PoseClip`/`PoseKey` 메모리 모델, 3개 이상 키의 구간 탐색·샘플링, 키 추가·선택·갱신·삭제, 중간 보간 프레임의 키 삽입·승격, 드래그 키 순서 변경, 위치·최단각·반지름·기본/관절/면 색상 보간, 애니메이션 JSON 저장·복원, 왕복 및 마지막→첫 키 연결 보간 재생, PNG/SVG 프레임 ZIP 내보내기.
- 다음 필수 수정: 보간 미리보기와 프레임 내보내기는 키 스냅샷의 월드 회전을 그대로 쓰지 않고, 활성 프레젠테이션 변환을 합성해야 한다. 현재 `interpolatePoseRig()`는 왼쪽 키의 리그를 복제한 뒤 관절 X/Y·각도·반지름만 보간하므로, 활성 월드 회전과 관절 Z가 중간 프레임에 일관되게 반영되지 않는다.
- 구현됨: 현재 리그의 관절 위치·회전·축 각도·깊이와 시점 값을 이름 붙인 사용자 포즈 프리셋으로 추가하고 다시 적용한다. 프리셋은 반지름·색상·자유 도형을 포함하지 않으며 브라우저 작업 자동 저장에 함께 보관한다.
- 기본 포즈 프리셋으로 `T 포즈`를 제공한다. 적용 시 현재 체형의 관절 간 길이와 반지름은 유지하고, 상체·팔·다리를 정면 T 자세로 정렬하며 시점 회전과 관절 깊이를 정면 기준으로 되돌린다. 기본 T 포즈는 삭제할 수 없고 사용자 포즈만 추가·삭제한다.
- 현재 체형 변경은 편집된 부모–자식 벡터의 방향을 유지하되 체형 프리셋의 절대 길이로 교체한다. 따라서 직접 이동으로 만든 각도는 유지되지만 부모와의 거리 변화와 측면 축소 표현은 초기화된다. 아래 `체형 독립 포즈 파라미터` 구조로 이 한계를 해소한다.
- 현재 키 데이터는 첫 구현 단계에서 호환 가능한 `Rig` 스냅샷을 보관한다. 아래 데이터 모델 초안은 프로젝트 저장 형식으로 정규화할 때의 목표 구조다.
- 보간 기능 내부의 다음 작업: 기존 두 키 사이의 전환 프레임 수 변경과 구간 눈금 UI. 다만 전체 프로젝트에서는 외형 제작과 게임용 출력이 우선이므로, 이 UI는 애니메이션 제작에 실제 병목이 될 때 진행한다. 클립 데이터는 도형·리그와 함께 저장하는 프로젝트 통합 저장 단계에서 연결한다.

## 1. 목표

한 개의 고정된 리그 구조에 `서기`, `팔 들기`, `걷기`처럼 여러 포즈 키를 저장한다. 사용자는 프레임 단위 타임라인의 재생 위치를 움직여 키 사이의 중간 자세를 확인하고, 같은 결과를 편집 미리보기와 PNG/SVG 출력에서 얻는다.

첫 단계는 관절 기반 2D 애니메이션에 집중한다. 새 키프레임을 만들 때 관절·면·부모 관계·축 ID는 바꾸지 않는다. 구조를 바꾸는 일은 기존 리그 편집 작업으로 분리한다.

## 2. 범위와 제외 항목

포함:

- 여러 포즈 키의 생성·이름 변경·복제·삭제·정렬
- 관절의 로컬 `x`, `y`, `localRotation`, 축 각도, 반지름 및 표시 상태 저장
- 인접한 두 키 사이의 프레임 눈금과 구간별 프레임 수 설정
- 키 사이의 미리보기 보간, 재생 위치 슬라이더와 중간 프레임 편집
- 보간 프레임을 두 인접 키 사이의 새 키프레임으로 승격
- 관절·면과 기본색의 색상 보간
- 타임라인 편집의 실행 취소/다시 실행, JSON 저장·복원, PNG/SVG 출력
- 보간 결과가 리그의 부모–자식 및 동등 그룹 규칙을 계속 만족하는지 검증

제외:

- 포즈 키와 같은 트랙에 월드/카메라를 무분별하게 섞어 저장하는 방식
- 보간 중 관절·면·부모 구조를 달리하는 기능
- 자유형 아트 도형, 텍스처, 물리 기반 애니메이션과 스켈레탈 IK

## 3. 데이터 모델 초안

프로젝트 문서는 리그와 포즈 클립을 함께 저장한다. 기존 단일 포즈 프리셋은 호환성을 위해 그대로 유지하고, 클립을 선택 적용할 때만 새 형식을 사용한다.

```ts
interface PoseKey {
  id: string;
  name: string;
  frame: number; // 0 이상의 정수, 같은 클립 안에서 고유
  joints: Record<string, {
    x: number;
    y: number;
    localRotation: number;
    axes: Record<string, number>;
    radius: number;
    bodyVisible: boolean;
  }>;
  colors: {
    defaultColor: string;
    joints: Record<string, string>;
    faces: Record<string, string>;
  };
}

interface PoseClip {
  id: string;
  name: string;
  fps: number;
  durationFrames: number;
  keys: PoseKey[];
}

interface PosePlaybackState {
  clipId: string | null;
  frame: number;
  isPlaying: boolean;
}
```

- 키에는 루트부터 모든 관절의 **로컬값**을 저장한다. 월드 좌표를 저장하면 부모 회전이나 계층 변경 뒤에 키의 의미가 달라진다.
- 인접 키의 `frame` 차이가 해당 구간의 프레임 수다. 사용자가 구간 길이를 바꾸면 오른쪽 키와 그 이후 키를 함께 이동해 뒤쪽 구간 길이는 보존한다.
- 키 생성 시 누락된 관절·축 ID를 허용하지 않는다. 현재 리그와 구조가 다른 클립은 읽기 전에 거부한다.
- 색상 키는 팔레트 ID가 아닌 렌더 시점의 실제 색상값을 저장한다. 팔레트는 편집 편의용 연결이고, 보간 결과 때문에 팔레트 항목을 프레임마다 생성하지 않는다.
- 포즈 키는 관절의 로컬 위치·회전·Z만 소유한다. 월드 회전, 카메라 Y 회전, 원근 설정은 아래 프레젠테이션 계층이 소유한다.

### 3.1 월드 회전과 애니메이션 프레젠테이션

월드 회전은 캐릭터 포즈가 아니라 현재 카메라에 보이는 장면의 변환이다. 따라서 재생 중에도 사용자가 바꾼 월드 회전은 모든 샘플 프레임에 즉시 적용되어야 한다.

```ts
interface RenderPresentation {
  worldRotation: { x: number; y: number; z: number };
  viewYRotation: number;
  perspectiveEnabled: boolean;
  projectionStrength: number;
}

function renderPoseSample(sampledPose: Rig, presentation: RenderPresentation): Rig {
  return {
    ...sampledPose,
    worldRotation: structuredClone(presentation.worldRotation),
    viewYRotation: presentation.viewYRotation,
    perspectiveEnabled: presentation.perspectiveEnabled,
    projectionStrength: presentation.projectionStrength,
  };
}
```

- 편집 미리보기, 재생, PNG/SVG 프레임 내보내기는 모두 `renderPoseSample()`을 거친 리그를 사용한다.
- 키 생성·수정·보간은 `worldRotation`을 변경하지 않는다. 키 선택으로 편집 리그를 복원할 때도 활성 프레젠테이션 변환은 보존한다.
- 월드 회전 자체를 애니메이션으로 만들 필요가 생기면 포즈 키에 넣지 않고 별도 `ViewTrack`을 둔다. `ViewTrack`은 X/Y/Z 월드 회전과 카메라/원근만 보간하며, 없는 경우에는 현재 활성 프레젠테이션 값을 사용한다.
- Z는 포즈 데이터이므로 관절 X/Y·반지름과 함께 보간한다. 월드 회전은 보간된 Z를 카메라 좌표로 투영하는 마지막 단계에서만 적용한다.

### 3.2 체형 독립 포즈 파라미터

현재 `Joint.x/y`는 체형의 부모–자식 기준 길이와 포즈의 방향·화면상 거리를 동시에 표현한다. 체형 프리셋은 현재 벡터의 방향을 정규화한 뒤 새 체형의 절대 길이를 곱하므로 각도는 유지하지만, 사용자가 직접 줄이거나 늘린 거리는 보존하지 못한다. 예를 들어 기준 길이 `96`인 팔을 측면 표현을 위해 `48`로 줄인 후 기준 길이 `69`인 아동체를 적용하면 현재 결과는 `69`이며, 의도한 `69 × 0.5 = 34.5`가 아니다.

다음 버전에서는 체형과 포즈의 소유 데이터를 분리한다.

```ts
interface JointBodyParameters {
  restLength: number; // 부모와의 체형 기준 거리
  restAngle: number;  // 체형의 부모 기준 기본 방향
}

interface JointPoseParameters {
  angleOffset: number;   // restAngle로부터의 포즈 회전
  distanceScale: number; // restLength에 곱하는 포즈 거리 배율, 기본 1
  localRotation: number;
  axes: Record<string, number>;
  depth?: number;
}
```

파생 좌표는 다음 규칙으로 계산한다.

```text
최종 각도 = restAngle + angleOffset
최종 거리 = restLength × distanceScale
x = cos(최종 각도) × 최종 거리
y = sin(최종 각도) × 최종 거리
```

- 일반 관절 드래그는 `angleOffset`만 갱신하고 기존 `distanceScale`을 유지한다. 3D 위치와 회전으로 깊이를 표현하므로 포즈 편집에서 관절 사이 거리를 바꾸지 않는 것이 기본이다.
- `Alt(Option)` 또는 `체형 길이 편집` 드래그만 연결 길이와 `distanceScale`을 갱신한다. 체형의 기준 길이인 `restLength`로 확정하는 작업은 체형 프리셋 저장·적용 흐름에서 처리한다.
- 체형 프리셋은 `restLength`, `restAngle`, 반지름과 동등 그룹 기준 간격만 바꾸고 포즈 파라미터는 유지한다.
- 포즈 프리셋은 `angleOffset`, `distanceScale`, 회전·축·깊이 값만 바꾸고 체형 파라미터는 유지한다.
- 최종 좌표는 부모부터 자식 순서로 다시 계산한다. `x/y`를 저장 원본으로 계속 병행하지 않고 파생 캐시 또는 렌더 입력으로 취급해 두 원본 데이터가 충돌하지 않게 한다.
- 어깨·골반처럼 부모–자식 외의 동등 관계는 `restPeerDistance × posePeerScale`을 별도 관리한다. 루트 이동도 체형 기준 위치와 포즈 오프셋을 분리한다.
- 같은 관절 ID와 부모 구조를 사용하는 체형 사이에서는 체형과 포즈의 적용 순서와 관계없이 같은 결과가 나와야 한다.
- 관절 구조가 다른 리그의 의미 기반 매핑, IK 목표, 관절 한계는 이 파라미터 분리만으로 해결하지 않으며 커스텀 리그 리타게팅 작업으로 분리한다.

측면 표현을 2D 거리 축소로 제작한 경우 `distanceScale`이 체형 간 동일한 축소율을 전달한다. 깊이를 사용하는 2.5D 포즈로 확장할 때는 절대 `depth` 대신 부모 기준 깊이 차이를 정규화한 `directionZ`를 추가하고, `distanceScale`은 의도적인 늘이기·압축에만 사용한다.

마이그레이션 시 기존 파일은 저장된 `x/y` 방향을 `angleOffset`으로 변환한다. 기존 데이터에는 독립된 기준 길이가 없으므로 기본 체형 또는 함께 저장된 체형의 길이를 `restLength`로 사용하고 `distanceScale = 현재 거리 / restLength`로 계산한다. 기준 체형을 판별할 수 없는 파일은 자동 추측하지 않고 현재 방식의 호환 모드로 읽는다.

## 4. 보간 규칙

1. 현재 프레임 양쪽의 키를 찾아 `t = (frame - left.frame) / (right.frame - left.frame)`을 계산한다.
2. `x`, `y`, `radius`는 처음에는 선형 보간한다.
3. `localRotation`과 축 각도는 0/360° 경계를 가로지를 때도 짧은 방향으로 보간한다.
4. `bodyVisible`처럼 연속값이 아닌 상태는 좌측 키 값을 유지하다가 다음 키 시점에서 전환한다. 교차 페이드가 필요해지면 별도 `opacity` 값으로 확장한다.
5. 색상은 처음에는 불투명 RGB/16진수 입력을 선형 RGB 값으로 변환해 보간한 뒤 렌더 색상으로 되돌린다. 알파를 지원할 때는 premultiplied alpha 규칙을 사용한다.
6. 보간 결과는 별도 미리보기 리그에 적용한다. 원본 편집 리그와 저장된 키 값을 재생 중 직접 변경하지 않는다.
7. 키가 하나뿐이면 해당 키를 그대로 표시한다. 첫 키 전과 마지막 키 후의 동작(고정, 반복, 핑퐁)은 재생 UI 추가 시 명시적으로 선택한다.

## 5. UI와 편집 흐름

1. 속성 패널에 `포즈` 탭을 추가한다.
2. 클립 목록에서 새 클립을 만들고, `현재 포즈를 키로 저장`으로 현재 프레임 위치의 키를 생성한다.
3. 타임라인에는 선택된 키 포즈 `A/B/…`를 표시하고, 인접한 두 키 사이에만 해당 구간의 중간 프레임 수를 눈금으로 표시한다. 클립 전체를 관통하는 불필요한 고정 눈금은 두지 않는다.
4. 키 사이 구간을 선택하면 `전환 프레임 수`를 정수로 입력할 수 있게 한다. 최소값은 1이며 변경 시 오른쪽 키와 이후 키의 프레임 위치를 함께 이동한다.
5. 재생 위치 슬라이더로 중간 프레임을 선택하면 보간 결과를 미리보고 편집 상태로 전환할 수 있다.
6. 중간 프레임에서 `키프레임으로 설정`을 실행하면 현재 보간 결과를 왼쪽·오른쪽 키 사이에 새 키로 삽입한다. 기존 두 키와 구간의 총 프레임 수는 유지한다.
7. 재생 위치 슬라이더, 재생/정지, 이전/다음 키 이동을 제공한다.
8. 키를 이동·복제·삭제할 때 같은 프레임에 두 키가 생기지 않게 하고, 삭제 뒤에는 최소 하나의 기준 키를 유지한다.

## 6. 프레임과 키 삽입 세부 규칙

- 구간 눈금은 두 키 사이의 중간 프레임만 나타낸다. 예를 들어 A가 0, B가 6이면 A와 B 사이에는 1–5의 다섯 눈금을 표시한다.
- 눈금은 프레임 선택을 위한 히트 영역을 가지되, 하단 패널이 다시 커지지 않도록 밀도에 따라 축약 표시한다. 프레임 수가 많으면 모든 숫자를 쓰지 않고 주요 눈금만 라벨링한다.
- 구간 프레임 수는 `오른쪽 키 프레임 - 왼쪽 키 프레임`으로 정의한다. 따라서 A=0, B=6은 A에서 B까지 6프레임에 걸쳐 변화하며 중간 보간 프레임은 5개다.
- 새 키는 반드시 두 인접 키의 열린 구간에만 삽입한다. 기존 키와 같은 프레임이 선택된 경우 새 키를 만들지 않고 해당 키를 선택한다.
- 새 키의 포즈와 색상은 선택 프레임에서 계산된 보간 결과를 복사한다. 삽입 직후에는 새 키가 선택되고 원본 보간 미리보기 잠금이 해제되어 직접 편집할 수 있어야 한다.
- 키 삽입 전후의 렌더 결과가 같아야 한다. 삽입 자체가 애니메이션 모양을 바꾸지 않으며, 이후 새 키를 수정할 때만 양쪽 구간 결과가 달라진다.
- 색상 보간은 기본색, 관절별 색상과 면별 색상에 같은 규칙을 적용한다. 한쪽 키에 명시 색상이 없으면 그 키에서 실제로 렌더되는 상속 색상을 사용한다.
- 색상과 포즈는 같은 `t`를 사용하되, 나중에 구간별 이징을 추가할 경우 위치·회전·색상의 이징을 독립 설정할 수 있도록 데이터 확장 여지를 둔다.

## 7. 구현 단계와 완료 기준

1. **상태 모델과 순수 보간 함수**: 프레임 기반 타입, 키 정렬·무결성 검사, 선형/최단각/색상 보간을 구현하고 단위 테스트를 추가한다.
2. **미리보기 렌더**: 재생 프레임의 파생 리그를 SVG와 PNG/SVG 출력에 연결한다. 원본 리그가 변하지 않는지 검증한다.
3. **키 편집 UI**: 클립·키 생성/선택/삭제, 구간 프레임 수, 구간 눈금, 중간 프레임의 키 승격과 타임라인 슬라이더를 추가하고 실행 취소 단위를 정의한다.
4. **저장과 호환성**: 클립이 포함된 프로젝트 저장 형식을 추가하며 기존 v1 포즈 프리셋은 계속 불러올 수 있게 한다.
5. **재생과 브라우저 검증**: 프레임 재생, 반복 정책, 포인터 편집 및 내보내기를 종단 간 검사한다.
6. **체형 독립 포즈 전환**: 체형 기준 거리·방향과 포즈 각도·거리 배율을 분리하고 직접 조작, 프리셋, 키프레임 보간이 같은 파라미터를 사용하게 한다. 성인체에서 부모 거리 `50%`로 편집한 팔이 아동체에서도 해당 체형 팔 길이의 `50%`가 되는지 검증한다.

완료 기준:

- 두 개 이상의 키 사이에서 팔·다리·몸통의 위치와 회전이 연속적으로 보간된다.
- 각 키 사이의 눈금 수가 설정한 구간 프레임 수와 일치하고, 다른 구간의 길이를 의도치 않게 바꾸지 않는다.
- 중간 보간 프레임을 새 키로 삽입해도 삽입 직전과 직후의 화면이 같고, 삽입 뒤 해당 키를 편집할 수 있다.
- 기본색과 관절·면의 색상이 키 사이에서 연속적으로 변하며 팔레트 데이터가 프레임마다 증가하지 않는다.
- 350°와 10° 같은 회전값도 20°의 짧은 경로로 움직인다.
- 재생과 미리보기는 원본 리그 및 키프레임 데이터를 누적 변형하지 않는다.
- 저장 후 다시 열어도 키의 프레임, 이름, 포즈와 동일한 중간 자세가 복원된다.
- 보간 중에도 연결 면, 레이어, 선택·드래그 및 PNG/SVG 출력이 일관되게 동작한다.
- 직접 관절 이동으로 만든 `distanceScale`이 체형 변경 뒤에도 유지되고, 체형을 먼저 또는 포즈를 먼저 적용해도 최종 좌표가 같다.
- 포즈 초기화는 `angleOffset = 0`, `distanceScale = 1`로 복원하며 체형의 `restLength`와 반지름을 변경하지 않는다.
