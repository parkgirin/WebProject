이 문서는 업데이트된 워크스페이스를 기준으로 렌더링 보정과 신체 확장 의상 작업의 실행 순서, 상태와 검수 항목을 한곳에 정리한 통합 일정이다.

- 현재 상태와 전체 우선순위: [현재 작업 진행 순서와 완료도](CURRENT_WORK_PLAN.md)
- 의상 최소 범위와 단계별 기술 결정: [신체 확장 의상과 렌더링 최소 일정](GARMENT_RENDERING_SCHEDULE.md)
- 게임 리소스 출력 이후의 전체 작업 순서: [다음 작업 일정](NEXT_WORK_SCHEDULE.md)
- 기존 리소스 출력 마일스톤: [리소스 출력 최소 기능 계획](RESOURCE_OUTPUT_MINIMUM_SCHEDULE.md)

문서 간 내용이 충돌하면 `CURRENT_WORK_PLAN.md`의 현재 상태와 `GARMENT_RENDERING_SCHEDULE.md`의 의상 범위를 우선한다. 정확한 날짜나 소요 시간을 고정하지 않고, 실제 출력 결과와 완료 조건으로 다음 단계 진입을 결정한다.

## 현재 상태

### 완료된 기반

- 체형·포즈·외형·고정 출력 시점의 v3 데이터 계약과 프로젝트 JSON 왕복
- 체형 독립 포즈와 XYZ 관절 거리 보존
- 고정 `outputView`와 별도 `worldRotationTrack`
- PNG/SVG 프레임 ZIP의 실제 파일 검증
- 균일 그리드 PNG 스프라이트 시트와 JSON 메타데이터 구현
- 자동·수동·선택 관절 추적 피벗과 프로젝트 저장·복원
- 숨김 `head` 관절을 사용한 프레임별 피벗 중앙 정렬 확인
- Unity 커스텀 임포터를 통한 Multiple Sprite와 `AnimationClip` 생성 확인
- 구워진 핑퐁 한 주기, 끝점 비중복과 XYZ 루트 이동 메타데이터 자동 검증

### 현재 진행 중

작업 단위 A의 실제 파일 검증을 완료하고 **R0 출력 렌더링 보정**을 진행한다.

- 출력 외곽선을 실제 가시 경계로 통일
- 원근과 X/Y/Z 회전의 중복 적용 여부 분리
- 정면·측면·45도 기준 포즈의 PNG/SVG 회귀 검증

### 다음 작업

R0을 마감한 뒤 구조·가이드·출력 레이어를 분리하는 R1으로 이동한다. 의상 기능부터 추가하지 않고 외곽선·원근 회전의 출력 문제를 먼저 보정한다.

## 고정 범위와 결정

- 렌더러가 직접 처리하는 표면 기본형은 **구**, **튜브**, 이후 추가할 **다중 관절 다각형** 세 종류로 제한한다.
- 팔·다리·목 같은 신체 부위 이름은 렌더 규칙이 아니다. 기존 `cameraFacingLimb`는 두 관절·두 반지름을 공용 튜브 입력으로 변환하는 어댑터로만 사용한다.
- 구는 중심·반지름·앞쪽 표면 깊이, 튜브는 시작/끝 중심·반지름·단면 기준축·끝단 상태, 다중 관절 다각형은 관절별 경계와 내부 패치로 정의한다.
- 가림, 교차선, 끝단 단면과 옆면 끝 곡률은 기본형 조합인 구–구, 구–튜브, 튜브–튜브, 다각형–기본형 비교로 계산한다.
- 원본 관절과 연결 튜브는 포즈, 애니메이션과 선택의 구조 기준으로 유지한다.
- 의상은 별도 뼈나 자유 메시가 아니라 원본 관절 체인의 표면 규칙을 상속한 **확장 표면**이다.
- 의상 편집은 원본 관절 거리, 부모 관계, 기본 깊이와 포즈 데이터를 변경하지 않는다.
- 의상 길이는 새 관절을 추가하지 않고 부모에서 자식으로 향하는 연결 면의 **로컬 축**에서 절단한다.
- 출력에서는 의상이 신체를 덮지만 편집에서는 가려진 원본 관절과 튜브를 가이드로 선택할 수 있다.
- 기존 자유 도형은 그대로 유지하며 의상 셸 형식으로 강제 변환하지 않는다.
- 편집 화면, 미리보기, PNG, SVG와 스프라이트 출력은 가능한 한 같은 변환·투영·가림 계산을 공유한다.
- `outputView`는 프로젝트 고정 출력 기준이며 카메라 애니메이션은 만들지 않는다.

## 단계별 일정

### A7 — 게임용 패키지 실제 파일 검증

#### 작업

1. 제자리 루프, 핑퐁, 루트 이동과 `worldRotationTrack` 표본을 각각 출력한다.
2. 외부 런타임에서 JSON의 FPS, 프레임 순서, 지속 시간과 피벗을 적용한다.
3. 이미지에서 분리한 프레임별 X/Y/Z 루트 이동량을 게임 오브젝트 위치에 적용한다.
4. 핑퐁의 첫·마지막 프레임이 의도치 않게 중복되거나 누락되지 않는지 확인한다.
5. 스프라이트 시트 셀을 다시 잘라 기존 PNG ZIP의 대응 프레임과 비교한다.
6. Unity 임포트 결과와 외부 재생 결과의 프레임 순서·피벗을 비교한다.

#### 완료 조건

- 일반 반복, 핑퐁과 루트 이동 표본을 외부 런타임에서 재현한다.
- JSON만으로 시트 자르기, 재생 순서, 피벗 배치와 루트 이동을 복원할 수 있다.
- 기존 PNG 프레임 출력과 스프라이트 시트에서 잘라낸 셀 사이에 의도하지 않은 차이가 없다.

### R0 — 출력 렌더링 보정

#### 목표

의상 셸을 추가하기 전에 편집 화면, 미리보기, PNG와 SVG의 실루엣·가림·회전 결과를 일치시킨다.

#### 작업

1. 출력 외곽선을 면·관절·튜브의 실제 가시 경계로 통일한다.
2. 내부 접합선이 최종 외곽선으로 남는 사례를 기준 포즈로 고정한다.
3. 카메라 투영, 관절 위치 회전, 표면 단면 회전과 월드 회전의 소유권을 분리한다.
4. 관절 X/Y/Z 회전은 하위 관절의 3D 위치에, 표면 회전은 튜브 단면 방향에 각각 한 번만 적용한다.
5. 원근 강도 변화가 관절 회전 각도를 증폭한 것처럼 보이는 사례를 회귀 테스트로 만든다.
6. 정면·측면·45도와 X/Y/Z 회전 포즈를 PNG와 SVG로 비교한다.

현재 원근 강도 변경이 모델 공간의 튜브 표면을 회전시키지 않는지, 월드 Z 회전이 관절 중심과 단면에 정확히 한 번만 적용되는지 자동 회귀 테스트를 추가했다. 이어 구형 관절 중심·반지름 투영을 공통 `projectSphereCircle()` 계약으로 분리하고 편집 SVG와 자동 출력 피벗 계산이 이를 공유하게 했다. 월드 X/Y 회전의 실제 SVG 관절·팔다리 출력도 같은 계약을 사용하는지 회귀 테스트로 확인한다.

관절 외곽선 마스크는 모든 형상을 무조건 가리개로 사용하지 않고, 렌더 깊이·그룹·레이어 순서상 해당 관절보다 실제로 앞에 그려지는 관절·면·절차 표면만 포함한다. 측면에 가까운 회전에서 뒤쪽 팔과 면이 앞쪽 손목 외곽선을 지우지 않는지 자동 검증한다.

단, 관절에 직접 연결된 튜브와 절차 표면은 일반 깊이 판정보다 연결 관계를 우선한다. 연결 튜브가 관절 외곽과 겹치는 구간은 두 형상의 내부 접합부이므로 튜브의 평균 깊이나 레이어 값과 무관하게 관절선을 가리고, 튜브 밖으로 노출된 관절 원호만 외곽선으로 남긴다.

큰 구형 표면과 튜브가 관통하는 경우에는 요소 중심의 단일 깊이 순서만 사용하지 않는다. 모든 표시 구와 튜브를 공용 표면 목록에 등록한 뒤 화면 경계와 앞·뒤 깊이 범위로 교차 후보를 먼저 줄인다. 후보가 아닌 쌍은 추가 표본 계산을 하지 않고, 후보 쌍만 튜브의 길이·단면 위치별 앞쪽 깊이와 구의 투영 위치별 앞쪽 표면 깊이를 비교한다. 그 결과 뒤에 들어간 부분만 국소 마스크로 제거하고 노출된 표면과 교차 경계를 남긴다. 머리–목처럼 연결된 쌍은 접합선 규칙을 추가로 적용하며, 머리–팔처럼 연결되지 않은 쌍도 같은 공용 깊이 규칙으로 가림을 계산한다.

1차 공용화는 `surface-geometry.ts`에 구·튜브의 화면 경계, 깊이 범위와 위치별 앞면 깊이 계산을 모은다. 렌더 순서는 기존 그룹·항목 순서를 유지하되, 실제 교차 영역에서는 이 순서보다 위치별 표면 깊이를 우선한다. 이후 다중 관절 다각형도 같은 표면 계약과 후보 선별 단계에 추가한다.

구 내부의 연결 튜브 외곽선은 채움 깊이 판정과 별도로 처리한다. 머리 구 투영 영역 안에 들어간 목의 세로 외곽선은 내부 접합선으로 제거한다. 서로 연결되지 않은 팔다리 튜브가 겹칠 때는 각 겹침 위치의 앞쪽 튜브 표면 깊이를 비교해 뒤쪽 채움과 외곽선을 국소적으로 가린다.

서로 다른 다리가 겹치는 경우 튜브–튜브뿐 아니라 튜브–관절 구도 같은 위치별 표면 깊이 규칙을 사용한다. 앞쪽 관절 구는 뒤쪽 튜브를 가리고, 앞쪽 튜브는 뒤쪽 무릎·발목 관절의 채움과 외곽선을 가린다. 연결된 자기 관절과 튜브는 이 교차 가림 대상에서 제외하고 접합 규칙을 따른다.

다리 사이의 안쪽 선은 별도 `leg-gap` 선을 마지막에 덧그리지 않는다. 각 다리 튜브의 양쪽 세로 외곽선을 원래 표면 항목 안에서 생성하고, 튜브–튜브·튜브–관절의 위치별 깊이 마스크가 뒤쪽 선을 직접 잘라낸다. 목 표면은 어깨 밴드·몸통과 같은 연결 표면군에 포함해 머리 구 내부뿐 아니라 어깨와 몸통 내부의 목 세로선도 제거하고, 계산된 머리–목 교차 곡선만 연결 경계로 남긴다.

굽힌 관절의 안쪽 선은 관절 원 외곽선이 우연히 남은 조각으로 표현하지 않는다. 관절에 연결된 앞·뒤 튜브의 안쪽 접점 두 개를 구하고, 굽힘 안쪽 방향을 지나는 관절 원호를 독립된 굴곡선으로 생성한다. 연결된 두 튜브는 이 선을 지우지 않으며, 카메라 앞쪽에 있는 다른 관절·튜브·표면만 굴곡선을 가릴 수 있다. 거의 곧은 관절은 굴곡선을 만들지 않는다.

몸체 채움은 최종 깊이·그룹·레이어 순서대로 뒤에서 앞으로 한 번만 그려 앞쪽 불투명 형상이 뒤쪽 픽셀을 덮게 한다. 모든 항목에 중첩 마스크를 만들지 않고, 실제 가시 경계 계산이 필요한 외곽선에만 깊이 인식 마스크를 제한해 렌더 비용과 마스크 경계의 점선형 아티팩트를 방지한다.

월드 Y `-79°`, 원근 강도 `35`의 기본 T포즈에서 기존 선형 배율이 양쪽 손목을 `0.5배`와 `1.5배` 한계까지 밀어 위아래 위치를 크게 벌리는 사례를 확인했다. 원근 배율을 완만한 초점거리 기반 곡선으로 변경하고, 같은 설정에서 손목 배율과 수직 이탈이 제한되는 회귀 테스트를 추가한다.

#### 완료 조건

- 내부선이 출력 외곽선으로 잘못 남지 않는다.
- 원근 강도를 바꿔도 관절 회전 자체가 과도하게 증폭되지 않는다.
- 관절 중심, 튜브 양 끝, 표면 단면과 외곽선이 같은 3D 변환 계약을 사용한다.
- X/Y/Z 회전이 위치와 표면에 의도치 않게 중복 적용되지 않는다.
- 편집 미리보기와 PNG/SVG의 실루엣과 가림 순서가 일치한다.

### T0 — 튜브 단면 후보 검토

정확한 방식은 아직 확정하지 않는다. 원, 타원과 원호 기반 가시 단면을 동일한 입력과 시점에서 비교한 뒤 G1에서 사용할 1차 방식을 선택한다.

#### 후보

- 원형 링 단면
- 폭과 깊이를 분리한 타원 단면
- 보이는 외곽 구간만 생성하는 원호 단면
- 타원 형상과 가시 원호 추출을 결합한 혼합 방식

#### 손목 끝단 단면 렌더 규칙 초안

1. 튜브 끝단에는 중심선에 수직인 로컬 단면을 만들고 원을 기본값으로 사용한다.
2. 단면 폭과 깊이가 다르면 투영 타원을 사용하며, 관절 표면 프로필이 있으면 해당 폭·깊이를 상속한다.
3. 손목 관절 구가 끝단을 덮는 구간은 캡을 그리지 않고 관절의 가시 원호가 끝단 경계 역할을 한다.
4. 관절 없이 노출된 끝단은 카메라를 향하는 반쪽 원호 또는 타원호와 내부 채움 캡을 생성한다.
5. 카메라 반대쪽 원호, 연결 튜브나 관절 내부로 들어간 원호는 출력하지 않는다.
6. 정면에 가까워 단면 투영 면적이 임계값보다 작아지면 원호 대신 짧은 끝선으로 안정화한다.
7. 원·타원·가시 원호 후보는 같은 손목 포즈에서 외곽 연속성, 뒤집힘, 픽셀 흔들림과 SVG 복잡도를 비교한 뒤 확정한다.

현재 1차 구현은 튜브 중심선에 수직인 3D 원을 32개 표본으로 투영한다. 카메라를 향하는 열린 끝단은 투영 타원 형태의 채움 캡과 전체 단면선을 렌더링한다. 단면 앞면이 측면이거나 반대쪽을 향해 보이지 않을 때는 별도 구형 반원을 붙이지 않고, 같은 3D 단면 원에서 카메라를 향하는 옆면 절반을 추출해 끝 곡선과 채움으로 사용한다. 손목·발목 관절 구가 표시되는 동안에는 관절의 노출 원호가 끝단 경계를 소유하므로 별도 튜브 끝단을 생성하지 않는다. 머리–목은 구와 튜브의 앞쪽 깊이가 같아지는 점을 단면 방향으로 추적해 별도의 연결 굴곡선을 생성한다.

열린 끝단 단면이 생성되면 숨김 관절의 보조 브리지 끝선은 생성하지 않아 동일 경계가 이중으로 표시되지 않게 한다. 머리–목 교차점 표본은 그대로 꺾은선으로 노출하지 않고 시작점·중간점·끝점을 통과하는 하나의 이차 곡선으로 안정화한다.

#### 비교 작업

1. 정면·45도·측면과 X/Y/Z 굽힘에서 각 후보의 단면을 생성한다.
2. 시작·끝 반지름이 다른 테이퍼 튜브와 일정 두께 의상 셸을 비교한다.
3. 포즈 보간 중 단면 시작점, 진행 방향과 꼭짓점 순서가 뒤집히지 않는지 확인한다.
4. 중간 절단 위치의 캡, 외곽선과 신체 가림 경계를 비교한다.
5. PNG와 그룹 병합 SVG의 실루엣 일치 여부와 계산 비용을 기록한다.

#### 완료 조건

- 후보별 비교 표본과 장단점이 기록돼 있다.
- `TubeSection`의 중심, 접선, 로컬 기준축, 폭·깊이, 가시 원호 범위에 대한 임시 계약이 있다.
- G1에 사용할 1차 방식과 보류할 대안이 정해져 있다.

세부 판단 기준은 [신체 확장 의상과 렌더링 최소 일정](GARMENT_RENDERING_SCHEDULE.md)의 T0을 따른다.

### T1 — 허리–골반 전이 다각형 검토

허리와 골반 사이의 최종 표면 처리는 아직 확정하지 않는다. 허리 관절 외곽과 골반 측 관절 또는 가상 캡슐의 투영 외곽을 경계로 전이 다각형을 먼저 만들고, 내부 채움과 분할은 별도 후보로 비교한다.

#### 작업

1. 각 관절 외곽에서 연결 방향의 지지점 또는 원호 구간을 선택한다.
2. 선택한 경계를 안정적인 순서로 연결해 바깥 다각형을 생성한다.
3. 단일 다각형, 삼각형/사각형 분할, 합집합·마스크와 복수 패치 방식을 비교한다.
4. 정면·45도·측면, 체형 차이와 허리·골반 회전에서 자기 교차와 순서 뒤집힘을 검사한다.
5. 내부선, 깊이 정렬, 의상 가림과 그룹 병합 SVG에 미치는 영향을 기록한다.

#### 완료 조건

- 허리·골반 관절 외곽을 경계로 하는 전이 다각형 표본이 있다.
- 외곽 생성과 내부 처리가 서로 독립된 계산 단계로 정의돼 있다.
- G1에서 사용할 1차 내부 처리 방식 또는 제한된 초기 범위가 정해져 있다.

세부 비교 표본과 후보는 [신체 확장 의상과 렌더링 최소 일정](GARMENT_RENDERING_SCHEDULE.md)의 T1을 따른다.

### T2 — 가슴·몸통 전이 표면 검토

좌우 어깨 캡슐, 가슴 관절과 허리 단면의 투영 외곽을 연결해 상체 실루엣을 만든다. 측면 가슴은 어깨 아래에서 시작하는 둥근 사각형을 1차 형태로 사용해 **갈비뼈의 앞·뒤·아래 외곽**과 모서리 곡률을 유지한다. 이 형상은 어깨 도형의 연장이 아니라 흉곽 실루엣이다. 외곽과 내부 처리를 분리하고, 단일 다각형·중앙/좌우 패치·어깨–가슴과 가슴–허리 분할·합집합 마스크 방식을 비교한다.

#### 작업

1. 어깨 안쪽 캡슐, 가슴과 허리 외곽에서 안정적인 대응 구간을 선택한다.
2. 어깨 안쪽 상단 앵커, 흉곽 폭·깊이·길이와 앞/뒤/아래 모서리 반경에서 로컬 둥근 사각형을 만들고 정면·45도·측면으로 투영한다.
3. 둥근 사각형 외곽을 허리 단면으로 연결해 앞가슴·등 깊이와 어깨 가림을 반영한다.
4. 체형과 상체 X/Y/Z 회전에서 대응점 순서, 틈과 자기 교차를 검사한다.
5. T1 허리–골반 전이 표면과 연결해 중복 외곽선과 빈틈을 확인한다.
6. 상의 셸이 가슴·허리를 덮을 때 사용할 가림 경계를 기록한다.

#### 완료 조건

- 어깨·가슴·허리 외곽을 경계로 하는 상체 전이 표면 표본이 있다.
- 측면에서 둥근 사각형 기반 갈비뼈·흉곽 외곽이 어깨부터 연속적으로 이어진다.
- 외곽과 내부 패치가 독립된 계산 단계로 정의돼 있다.
- T1 표면과 연결했을 때 틈·중복 외곽선·자기 교차가 없다.

### F0 — 얼굴 면 기본 구조

머리 구를 유지하면서 눈·코·입·볼·턱을 배치할 얼굴 면을 별도 표면 계층으로 추가한다. 얼굴 면은 머리 중심과 로컬 기준축으로 정의하고 머리 관절, 체형, 포즈와 월드 회전을 따른다.

이 문서의 얼굴 면은 캐릭터 얼굴 표면을 뜻하며 기존 리그 연결 타입 `Face`로 확정하지 않는다. `ArtShape` 확장 또는 별도 표면 타입 여부는 비교 뒤 결정한다.

#### 작업

1. 정면 중앙 면과 좌우 볼·턱을 표현할 최소 패치 후보를 만든다.
2. 눈·코·입 도형이 참조할 안정적인 로컬 기준점 또는 좌표를 정한다.
3. 정면·좌우 45도·측면에서 얼굴 면과 반대쪽 요소의 표시·가림을 비교한다.
4. 머리 구, 얼굴, 머리카락과 장식의 출력 그룹·깊이 순서를 정의한다.
5. 저장·복원, 포즈, 월드 회전과 PNG/SVG 출력에서 참조를 검증한다.

#### 완료 조건

- 기본 얼굴 면이 머리 관절과 머리 구를 따라 모든 기준 시점에서 유지된다.
- 눈·코·입을 배치할 로컬 기준이 있다.
- 얼굴·머리·머리카락의 가림과 출력 순서가 정의돼 있다.

정밀 얼굴 메시, 표정, 립싱크와 텍스처는 이 단계의 범위가 아니다.

### R1 — 리그 구조와 렌더링 표현 분리

#### 출력 상태

원본 관절과 연결 면은 삭제하지 않고 다음 상태를 갖는다.

| 상태 | 편집 화면 | 최종 출력 |
| --- | --- | --- |
| `visible` | 표시·선택 | 원본 신체 표시 |
| `guide-only` | 가이드 표시·선택 | 숨김 |
| `covered` | 가이드 표시·선택 | 지정한 의상이 덮은 구간 숨김 |

의상은 가림 대상 관절 체인 또는 연결 면을 안정적인 ID로 참조한다.

#### 작업

- 구조용 리그 상태와 출력용 가시 상태를 분리한다.
- 가이드 표시 여부가 출력 렌더 목록에 섞이지 않게 한다.
- 의상 제거 또는 가림 해제 시 원본 신체가 즉시 복원되게 한다.
- 출력 상태를 v3 프로젝트 저장·복원과 실행 취소·다시 실행에 연결한다.

#### 완료 조건

- 긴소매가 `shoulder → elbow → wrist`를 덮어도 세 관절을 모두 선택·회전할 수 있다.
- 가이드 표시를 켜거나 꺼도 PNG/SVG 결과가 달라지지 않는다.
- 의상 가림 해제 후 원본 신체 렌더링이 손실 없이 복구된다.

### G1 — 관절 단위 확장 표면

#### 데이터 범위

의상 확장 표면은 원본 관절 ID를 참조하고 다음 값만 추가한다.

- 반지름 또는 표면 폭 확장값
- 로컬 X/Y/Z 표면 스케일과 두께
- 색상 또는 재질 참조
- 출력 레이어와 `exportGroupId`
- 인접 원본 관절과의 의상 연결 여부
- 덮을 원본 체인 또는 연결 면 참조

#### 작업

1. 기존 팔다리 카메라 대응 면 계산을 재사용 가능한 튜브 단면 계산으로 분리한다.
2. 신체 튜브와 의상 셸이 중심선, 깊이, X/Y/Z 회전과 원근 투영을 공유하게 한다.
3. 긴소매 하나를 첫 기준 에셋으로 구현한다.
4. 같은 규칙을 긴바지와 손목·발목에서 끝나는 단순 장갑·부츠로 확장한다.
5. 체형 프리셋 전환, 포즈 보간, 월드 회전과 프로젝트 왕복을 검증한다.

#### 완료 조건

- 정면·측면·45도 포즈에서 소매와 바지가 원본 튜브를 따라간다.
- 체형을 변경해도 확장량과 체인 연결이 유지된다.
- 포즈 전후 원본 관절 거리 비율이 100% 유지된다.
- 의상 편집이 원본 리그의 부모 관계, 기본 깊이와 포즈를 변경하지 않는다.

### G2 — 연결 면의 로컬 축 절단

#### 저장 규칙

- `cutStart`: 부모 관절 쪽에서 숨길 구간
- `cutEnd`: 자식 관절 쪽에서 숨길 구간
- 값은 연결 면의 로컬 길이에 대한 `0..1` 비율 또는 명시적인 로컬 길이로 저장
- 화면 X/Y와 고정 월드 좌표는 절단 기준으로 사용하지 않음

#### 작업

1. 절단 위치에서 의상 면, 캡과 외곽선을 함께 생성한다.
2. 반소매는 어깨–팔꿈치 면의 자식 쪽 절단으로 표현한다.
3. 7부 소매는 팔꿈치–손목 면의 중간 절단으로 표현한다.
4. 반바지는 엉덩이–무릎 면의 로컬 축 절단으로 표현한다.
5. 포즈, 원근과 체형을 바꾼 뒤에도 같은 신체 부위에서 끝나는지 확인한다.

#### 완료 조건

- 같은 의상 정의가 포즈·원근·체형 변화 후에도 같은 신체 부위에서 끝난다.
- 절단면의 캡, 외곽선과 신체 가림이 모든 출력 형식에서 일치한다.
- 절단 위치 변경이 원본 관절 위치나 연결 길이를 변경하지 않는다.

### B3 — 출력 그룹별 병합 SVG

#### 작업

- 출력 그룹별로 투영된 원, 튜브, 의상 셸과 자유 도형을 수집한다.
- 같은 그룹의 겹치는 채움 영역을 하나 이상의 경계로 병합한다.
- 그룹 내부 접합선은 제거하고 그룹 간 경계는 유지한다.
- 카메라 거리, 명시적인 레이어 순서와 `exportGroupId`를 보존한다.
- 관절 가이드, 축, 선택 표시와 편집 핸들은 병합 대상에서 제외한다.
- 열린 경계나 자가 교차로 병합할 수 없는 형상은 원본을 손상시키지 않고 오류로 보고한다.

#### 완료 조건

- 몸통, 팔, 소매 표본이 편집 미리보기와 같은 실루엣을 유지한다.
- 같은 출력 그룹의 내부 접합선이 없는 SVG가 생성된다.
- 신체와 의상을 별도 출력 그룹으로 지정했을 때 각 경계와 순서가 유지된다.

### G3 — 파일·에셋 통합 검증

#### 필수 표본

1. 정면 기본 포즈의 긴소매·긴바지
2. X/Y/Z 회전이 있는 팔·무릎 포즈의 반소매·7부 바지
3. 기본 깊이가 다른 두 체형에 같은 포즈와 의상을 적용한 표본
4. PNG, SVG, 스프라이트 시트·JSON, 프로젝트 JSON 재불러오기와 Unity 임포트 표본

#### 검증 항목

- 편집 화면과 내보내기 미리보기의 가림·길이·레이어 비교
- PNG/SVG와 Unity 스프라이트의 실루엣·피벗·프레임 순서 비교
- 저장·재불러오기와 체형 전환 뒤 원본 리그·의상 참조 확인
- 외곽선·원근 회귀 자동 테스트와 실제 파일 비교
- 의상 없는 기존 프로젝트의 렌더 결과가 변하지 않는지 확인

#### 완료 조건

- 모든 출력과 Unity 결과에서 의상 가림, 길이, 실루엣과 레이어가 일치한다.
- 프로젝트 왕복과 체형 전환 뒤에도 원본 리그와 의상 참조가 유지된다.
- 자동 테스트, 프로덕션 빌드와 실제 파일 점검을 모두 통과한다.

### B4 — 교차 경고

- 포즈 재생 구간에서 의상 셸과 신체 튜브의 부분 교차 후보를 검사한다.
- 경고에 클립, 프레임과 관련 형상 ID를 포함한다.
- 첫 범위에서는 자동 깊이 절단이나 형상 수정을 수행하지 않는다.
- 비교차 포즈에서는 외곽선 누락과 출력 변동이 없어야 한다.

완료 조건은 알려진 교차 표본을 정확한 프레임과 형상으로 경고하고, 정상 표본에는 불필요한 경고나 출력 변화가 없는 것이다.

## 단계 전환 규칙

- A7의 외부 런타임 검증을 마감한 뒤 R0을 시작한다.
- R0의 변환·외곽선 계약이 안정된 뒤 T0 후보 비교를 시작한다.
- T0에서 1차 단면 방식과 임시 `TubeSection` 계약을 정하기 전에는 의상 셸을 렌더러에 추가하지 않는다.
- T0의 임시 단면 계약으로 T1 허리–골반 외곽 다각형을 검토한다.
- T1에서 외곽 생성과 내부 처리의 1차 범위를 정하기 전에는 허리·골반 의상 연결을 구현하지 않는다.
- T1과 같은 외곽·내부 분리 원칙으로 T2 가슴·몸통 전이 표면을 검토한다.
- 기본 캐릭터 출력에 F0 얼굴 면과 얼굴 요소 배치 기준을 마련한다.
- R1에서 구조와 출력 가시 상태를 분리하고 T0–T2·F0의 기하 계약을 확정한 뒤 G1의 가림 규칙을 연결한다.
- G1의 긴소매가 정면·측면·45도, 체형 전환과 애니메이션을 통과한 뒤 긴바지·장갑·부츠로 확장한다.
- G1의 전체 체인 셸이 안정된 뒤 G2의 부분 절단을 구현한다.
- B3 병합 결과가 실루엣을 바꾸면 병합 전 투영 형상과 R0 변환 계약을 먼저 확인한다.
- G3의 실제 파일과 Unity 검증을 통과한 뒤 의상 작업 단위를 완료로 표시한다.
