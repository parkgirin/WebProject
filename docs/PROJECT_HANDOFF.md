# Pose Mesh Editor — 기획 및 작업 인계서

## 1. 프로젝트 목적

그림을 직접 그리는 부담을 줄이기 위해, **원형 관절과 연결 면으로 2D 캐릭터를 만들고 포즈를 편집하는 웹 도구**를 만든다.

최종적으로는 2D 기반이지만 관절 위치·크기·축선별 회전·앞뒤 레이어를 조절해 3D처럼 보이는 자세를 만들 수 있어야 한다. 스토리용 캐릭터를 대상으로 하며, 복잡한 실시간 물리나 3D 모델링은 범위 밖이다.

## 2. 확정된 시각·리그 규칙

- 캐릭터 비율의 기본은 **5등신 남성체**다.
- 기준 SVG `Grid_Img.svg`는 `250 × 500`이며 편집기에서는 `1.2배`인 `300 × 600`으로 표시한다. SVG 작업 영역의 `(150, 80)`에 배치하면 중심선 `x=300`과 5등신 기준선 `y=80~680`에 정확히 맞는다.
- 확정한 7종 비율 프리셋의 앱 좌표·반지름·관절 위치는 `AVATAR_PROPORTION_PRESETS.md`를 기준으로 한다.
- 7종 체형은 캔버스 상단 선택 상자에서 적용할 수 있다. 적용 시 연결 방향·회전·색상·가상 중심 오프셋은 유지하고 길이와 반지름만 바꾸며, 전체 변경은 한 번에 실행 취소된다.
- 캐릭터는 정면과 좌·우 3/4 방향을 주로 사용한다. 완전 측면은 우선순위가 낮다.
- 기본 제공 직선형 인체는 양팔을 어깨 높이로 작성했지만, 포즈 초기화는 고정 T 포즈가 아니라 활성 체형의 `baseOffset`을 복원한다.
- 전체 기본색을 사용하되 면과 출력용 관절 원에는 선택적인 개별 색상 덮어쓰기를 지정할 수 있다.
- 관절은 원으로 표현한다. 각 원은 `위치`, `반지름`, `축선 배열`을 가진다.
- 각 축선은 관절 중심을 지나며 고유 ID, 독립된 각도, 사용할 원주 끝점을 가진다.
- 한 관절에서 만나는 면마다 다른 축선을 참조할 수 있어 각 면 경계의 기울기를 독립적으로 조절한다.
- 기본 인체 리그는 관절당 축선을 최대 3개 사용하지만 편집·검증 정책은 자유 도형용 수동 축을 위해 최대 8개를 허용한다. 고관절은 골반 가로·세로 경계와 허벅지 연결을 분리해 기본 세 축을 사용한다.
- 레이어 패널은 관절·축 가이드·연결 면·자유 도형을 사진 편집 앱과 같은 네 전역 레이어로 제공하고 각 레이어 전체를 일괄 표시·숨김한다. 내부 항목에는 개별 표시 스위치를 두지 않는다. 관절·면·도형은 통합 출력 스택을 공유하고, 축은 출력 순서에 참여하지 않는 편집 가이드 레이어다.
- 좌우 어깨는 저장된 관절 중심을 몸통 쪽 안쪽 구로 사용하고, 반대쪽 어깨에서 멀어지는 방향으로 반지름만큼 연장되는 단방향 캡슐이다. `shoulder-band`의 간격·회전은 상체 폭을 조정하고, 개별 어깨 캡슐 길이는 바깥 구에 연결된 팔 전체의 바깥쪽 위치를 조정한다. 위팔 회전과 연결면은 파생된 바깥 구를 기준으로 하지만 끝 구의 직접 선택 UI는 아직 제공하지 않는다.
- 좌우 고관절은 `pelvis-pivot`을 중심으로 하는 `hip-band` 가상 캡슐이다. 고관절에는 다리 연결용 `upper-leg` 축만 남기며, 과거의 `pelvis-vertical`·`pelvis-horizontal`, 허리 `pelvis` 축과 중앙/좌우 골반 면은 로드 시 제거한다.
- 팔다리·목·가상 캡슐은 두 관절의 중심과 반지름에서 카메라 방향 단면을 계산해 생성한 절차적 면이다. 몸통과 `waist-hip`은 각각 어깨–허리, 허리–골반의 3D 캡슐 단면을 투영한 뒤 연결 방향에 수직인 좌우 지지점 네 개로 카메라 방향 사각형 하나를 만든다. 직선형 기본체에서는 단면 폭이 같아 수직 실루엣을 유지한다.
- 기본 축은 해당 관절의 하위 관절과 연결 면을 회전시키는 조작 핸들만 남기며, 부모–자식 중심선에 직교하는 연결 면 단면 방향으로 자동 정렬한다. 들어오는 연결 면 전용 축은 저장하지 않으며 자유 도형용 `art-axis-*`는 별도로 유지한다.
- 한 면의 꼭짓점 순서는 고정한다. 관절 중심 간의 교차점을 매 프레임 새로 찾지 않는다.
- 사지 면은 두 관절의 화면상 원 단면을 잇는 4점 사다리꼴이다.
  - 예: `어깨 바깥 → 팔꿈치 바깥 → 팔꿈치 안쪽 → 어깨 안쪽`
- 몸통과 골반은 저장된 면 경계축 대신 투영된 캡슐 단면의 지지점 네 개로 절차 생성한다. 어깨에는 위팔 조작용 `upper-arm`, 허리에는 상체 조작용 `upper-torso`, 고관절에는 허벅지 조작용 `upper-leg`만 남긴다.
- 손목은 생략하지 않고 관절과 축선을 가진다. 관절 원의 출력 표시 여부로 연결부를 둥글게 덮을지 면 끝을 그대로 보일지 선택한다.
- 머리와 목의 위쪽 연결점은 하나의 `head` 관절 중심을 공유한다. `head.radius`는 목 연결과 편집 가이드 크기이며, 실제 머리는 이 중심에 연결된 독립 `sphere` ArtShape인 `head-base`로 그린다.
- 목은 가슴의 `neck` 조작축으로 머리를 회전시키고, 표면은 `chest`–`head` 중심과 반지름에서 생성한다. 머리에는 중복 `neck` 축을 두지 않는다.
- 관절 원은 편집 화면에서는 보이지만, 실제 캐릭터 출력에서는 숨길 수 있다.
- 숨긴 관절은 연결된 절차적 면에서 해당 관절의 화면 단면을 수집해 볼록 bridge로 마감한다. 연결면용 축 교차나 골반 전용 접선 계산은 사용하지 않는다.
- 손·발은 끝 관절에 붙는 선택 파츠다. 끝 관절은 숨겨도 리그 계산과 팔·다리 끝 폭 결정에는 사용한다.

## 3. 구현 기술 결정

### 초기 편집기: SVG

관절 드래그, 축선 선택·회전 핸들, 축 끝점, 연결 면의 선택·레이어 표현은 SVG로 구현한다.

SVG를 선택한 이유:

- 관절 원·다각형·핸들이 각각 독립된 요소라 선택과 드래그가 쉽다.
- 면의 꼭짓점과 레이어를 디버그하기 좋다.
- Canvas만으로 시작했을 때 필요한 히트 테스트와 전체 재렌더링을 피할 수 있다.

### 이후 아트 렌더러: Canvas

캐릭터 그림·질감·브러시 결과는 나중에 Canvas 레이어로 분리한다. 현재 면의 단색은 연결 관계를 보기 위한 임시 디버그 표현이며 최종 아트 속성이 아니다.

```text
Canvas: 실제 그림·색·질감
SVG: 관절, 다중 축선과 끝점, 연결 면 윤곽, 회전 핸들, 선택 표시
```

리그의 구조 데이터와 아트 데이터를 분리한다. `Face`는 나중에 파일 경로나 URL을 직접 저장하지 않고 `materialId` 또는 `assetId`로 별도 아트 자원을 참조한다. 외부에서 가져온 텍스처를 포즈에 따라 휘게 하려면 면을 안정적인 삼각형으로 나누고 UV 좌표와 함께 Canvas 또는 WebGL에서 매핑한다. 초기 버전에서는 연결 확인용 단색 SVG 면만 구현한다.

## 4. 데이터 모델 초안

```ts
interface Joint {
  id: string;
  x: number;
  y: number;
  radius: number;
  bodyRadius?: number; // 임시 미리보기 전용. 이후 관절 바인딩 ArtShape로 이전
  color?: string; // 전체 기본색과 다르게 표시할 출력용 관절 원에만 사용
  groupId?: string;
  axes: JointAxis[];
  renderOrder: number;
  guideVisible: boolean;
  bodyVisible: boolean;
  outlineVisible?: boolean;
  faceExtensionEnabled?: boolean;
}

interface JointAxis {
  id: string;
  angle: number;
  pointSides: (-1 | 1)[];
}

interface JointPointRef {
  jointId: string;
  axisId: string;
  side: -1 | 1;
}

type FaceRotationTarget =
  | { type: "child"; childJointId: string }
  | { type: "peer"; peerGroupId: string; referenceJointId: string };

interface Face {
  id: string;
  vertices: JointPointRef[]; // 꼭짓점 순서가 곧 면의 위상
  rotationTarget: FaceRotationTarget; // 면 이름과 무관한 공통 회전 규칙
  color?: string; // 전체 기본 색상과 다르게 표시할 때만 사용하는 선택적 덮어쓰기
  groupId?: string;
  layerOrder?: number; // 같은 그룹 안에서 관절과 면을 함께 정렬하는 명시적 순서
  orderOffset: number;
}

interface LayerGroup {
  id: string;
  name: string;
  visible: boolean;
  order: number; // 그룹끼리 겹칠 때의 렌더 순서. 값이 클수록 앞에 표시
}

interface Rig {
  defaultColor: string; // 모든 면과 출력용 관절 원이 공유하는 기본 색상
  groups: LayerGroup[];
  joints: Joint[];
  faces: Face[];
}
```

향후 아트 데이터는 다음처럼 리그와 분리한다.

```ts
interface Material {
  id: string;
  type: "solid" | "texture";
  color?: string;
  assetId?: string;
}

interface TextureAsset {
  id: string;
  source: "imported" | "generated";
  fileName: string;
}
```

현재는 `Rig.defaultColor`를 전체 기본색으로 사용하고 `Face.color`가 존재하는 면만 별도 색상으로 덮어쓴다. 최종적으로 이 색상 필드는 `materialId` 참조로 대체한다. 관절을 출력에 표시할지 여부는 `bodyVisible`이 담당하고, 실제 관절부 그림과 질감은 별도 아트 계층에서 결정한다.

축 끝점의 화면 좌표 계산:

```text
worldPoint = jointCenter
  + direction(axis.angle)
  × joint.radius
  × side
```

면 꼭짓점은 `(jointId, axisId, side)`로 사용할 축선을 명시한다. 포즈는 리그 구조를 복제하지 않고 관절별 `x`, `y`, `radius`와 축선별 `angle` 변경값을 저장하며, 포즈 전환 애니메이션은 이 값들을 시간에 따라 보간한다.

## 5. 첫 구현 목표 (MVP)

1. 고정 5등신 그리드가 있는 SVG 편집 화면
2. 기본 편집 관절 15개와 가상 장면 루트 표시
3. 관절 중심 드래그
4. 선택한 관절의 반지름 조절
5. 축선을 선택하고 회전 핸들로 해당 `angle` 변경
6. 축선별 끝점 좌표 계산
7. 팔 하나를 사다리꼴 연결 면으로 자동 생성
8. 모든 변경을 즉시 SVG에 반영

기본 SVG 편집 MVP와 고정 인체 템플릿(`human-v1`) 기반 JSON v2 프리셋 저장·불러오기, PNG/SVG 출력, GitHub Pages 자동 배포는 구현되었다. 실제 캐릭터 아트, Canvas 질감과 애니메이션은 아직 구현하지 않는다.

## 8. 로컬 실행과 배포

- 프로젝트 위치: `C:\WebProjects\WebProject`
- PowerShell 실행 정책 때문에 `npm` 대신 `npm.cmd`를 사용한다.

```powershell
cd C:\WebProjects\WebProject
npm.cmd install
npm.cmd run dev
npm.cmd test
npm.cmd run build
```

개발 서버는 로컬 전용이며, 보통 `http://localhost:5173/`에서 열린다.

원격 저장소: `https://github.com/parkgirin/WebProject.git`

GitHub Pages에는 Vite의 빌드 결과물인 `dist/`를 배포한다. 공개 주소는 배포 후 일반적으로 아래 형태다.

```text
https://parkgirin.github.io/WebProject/
```

현재 `vite.config.ts`는 상대 경로 배포를 위한 `base: "./"`를 사용한다.

- 부모–자식 관절을 직접 잇는 면은 단면 축을 연결선에 직교시키며, 해당 축 회전은 연결된 자식과 전체 하위 트리를 함께 회전시킴
- 기본 인체 리그는 머리·목 중심 공유, 어깨·몸통 분리, 손목, 중앙 사각형과 좌우 삼각형 골반, 허벅지·종아리 면까지 구현됨
- 기준 SVG를 배경에 겹쳐 기본 관절 위치와 크기를 확인할 수 있음
- 그룹 및 항목 레이어, 팔레트 연동 색상, 선택적 관절 표시와 외곽선 규칙이 구현됨
- 포즈·비율·색상을 `human-v1` 템플릿 기반 JSON v2 파일로 저장하고 원하는 항목만 선택해 불러올 수 있음
- 투명 배경 PNG/SVG 저장과 저장 미리보기가 구현됨
- GitHub Pages 자동 배포 워크플로가 구현됨
- Node 기본 테스트 실행기로 리그 검증, 계층 회전, 부모 변경, 히스토리와 프리셋 복원을 자동 검증함
- v3 프로젝트 JSON은 리그·신체·포즈·외형·고정 출력 시점과 포즈/월드 회전/외형 애니메이션 트랙을 분리해 저장하고 다시 불러올 수 있음
- 내장 T 포즈는 제거했으며, 기본 포즈 초기화·팔 수직 내리기·팔다리 30° 포즈는 활성 체형의 `baseOffset`을 기준으로 적용함
- 남은 핵심 결함: Z 회전만 저장한 v2 포즈를 다른 체형에 적용해도 저장된 관절 좌표가 대상 `baseOffset`을 덮어써 변형될 수 있음. v3 포즈 파라미터를 프리셋 적용 런타임에 연결해야 함

## 11. 기본 구현 이후 고려 사항

- 포즈와 비율은 별도 클립보드 JSON으로 복사·붙여넣기를 지원한다. 포즈는 관절 위치·축선 각도, 비율은 기본 리그의 관절 반지름·상대 위치를 대상으로 하며, 둘 다 스키마 버전과 리그 호환성 검증을 거친다.
- 프로그램은 PWA로 설치 가능하게 만들어 오프라인에서도 기본 편집, 포즈/비율 복사, PNG/SVG 출력을 지원한다. 외부 이미지 가져오기처럼 네트워크가 필요한 기능만 오프라인에서 제한한다.
- 관절과 면의 관계마다 `-1`(관절 뒤), `+1`(관절 앞)을 지정한다. 같은 부호에 여러 면을 허용하고 별도 보조 순서로 안정적으로 정렬한다.
- 한 면이 관절마다 서로 다른 앞뒤 관계를 가지면 단일 SVG 다각형으로 표현할 수 없으므로, 초기 제한 또는 삼각형/렌더 조각 분할이 필요하다.
- 기본 팔다리는 `left-arm`, `right-arm`, `left-leg`, `right-leg`로 나눈다. `관절 끝선 숨김`이 켜지면 한 면에서 같은 관절의 두 축 끝점을 잇는 선분만 그리지 않는다. 서로 다른 관절을 잇는 팔·다리의 길이 방향 외곽선과 다른 그룹이 겹치는 경계는 남아 앞쪽 도형을 구분할 수 있다.
- `LayerGroup.order`로 그룹 전체의 앞뒤를 정하고, `layerOrder`는 해당 그룹 내부에서 관절과 면의 순서를 정한다. SVG 편집 화면, 저장 미리보기와 PNG/SVG 출력은 같은 그룹 순서와 선택적 외곽선 규칙을 사용한다.
- 관절은 부모 ID와 로컬 위치·회전을 저장하고 월드 행렬을 계산한다. 어깨의 변환은 팔꿈치와 손목으로, 고관절의 변환은 무릎과 발목으로 전달한다.
- 속성 패널에서 관절의 부모를 선택·변경할 수 있게 하고, 현재 월드 포즈를 유지한 채 새 부모 기준 로컬 값으로 변환한다. 부모–자식 관절을 잇는 가이드 선과 끝 핸들은 회전 조작에 사용하며, 선을 회전하면 해당 자식 하위 트리만 함께 회전한다.
- 관계는 실제 변환 계층인 `parent-child`와 동등 관계인 `peer`로 구분한다. 팔은 어깨 중심의 부모–자식 회전을 사용한다. 두 관절 동등 그룹은 중심 간격을 중점 기준으로 대칭 조절할 수 있다. 가상 부모가 있으면 동등축 X·직교축 Y 오프셋으로 회전 중심만 재배치하며 현재 포즈는 유지한다. 이후 가상 중심 핸들 회전 시 오프셋 피벗을 기준으로 구성원과 각 하위 트리가 함께 회전한다.
- 얼굴형, 머리카락, 옷, 장식은 연결 면과 다른 `ArtShape`로 관리한다. 현재 자유 다각형, 선택 면 참조 복제와 두께 선분을 지원하며 각 꼭짓점/끝점은 루트 또는 관절 축 끝점에 연결할 수 있다.
- `ArtShape`는 관절 또는 면에 가중치로 바인딩하고 이동·회전·변형 영향도를 `0..1` 파라미터로 조절한다.
- 면 바인딩은 고정 삼각형과 barycentric 좌표를 사용해 상위 면의 이동과 변형을 안정적으로 따른다.
- 정면과 좌·우 측면은 같은 관절·면·정점 위상을 가진 시점 기준 형상으로 저장한다. `viewAngle`은 포즈 회전과 분리하고, 기준 형상 사이의 관절 위치·실루엣 정점·깊이·표시 상태를 보간해 중간 시점 이미지를 만든다.
- `head` 관절도 다른 관절과 동일한 부모–자식 변환 규칙을 사용한다. 머리 구는 관절 본체와 별개이므로 도형 레이어·색상·합성 순서로 편집한다. 모든 면은 이름별 분기 없이 `rotationTarget`으로 회전 대상을 선언한다.
- `ArtShape`는 하나 이상의 관절 또는 면을 바인딩 대상으로 참조하고 `translationInfluence`, `rotationInfluence`, `deformationInfluence`를 각각 `0..1`로 저장한다. 머리 미리보기는 초기에는 `head` 관절 이동 영향 `1`, 회전 영향 `1`, 변형 영향 `0`인 원형 도형으로 이전한다.
- 유사 3D 시점 변형은 현재 구현을 보류한다. 재개할 때는 단순한 가로 축소가 아니라 코·턱·후두부·어깨처럼 윤곽을 결정하는 부분의 위치 보정과 눈·귀·팔의 앞뒤 전환을 함께 처리하며, 비대칭 요소는 좌·우 측면 키를 따로 가진다.
- 장기 기능 범위와 구현 순서는 `plans/GENERAL_EDITOR_FEATURES.md`의 외형·레이어·출력 및 장기 구현 순서를 따른다.
- 상세 데이터 구조와 충돌 규칙은 `GRAPHICS_GENERATION_SPEC.md`의 구조 확장 절을 기준으로 한다.
